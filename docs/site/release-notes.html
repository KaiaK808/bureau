Bureau v3.5.0 — coordinated dispatch, evidence and bounded recovery

Stable release · 2026-10-28 · source tag v3.5.0 · prepared 2026-10-27. The GitHub Release is marked as latest and records the exact tagged commit. Tagging and publication remain separate maintainer operations. The previous stable release is v3.4.1; its notes retain the earlier release history.

v3.5.0 is a minor release on v3.4.1. It collects #76–#94 and the Spec Kit 1.2.2 upgrade in #75. The v3 exit vocabulary gains 28 and 29; scripts and interfaces must be resynced together. It goes straight to stable without a release candidate.

What changed since v3.4.1

Shell inputs and the child environment

Numeric settings are validated after source selection and before arithmetic. Invalid values use bounded defaults and warnings name only the key; leading zeros in inherited values and JSON digit strings are decimal. Supervisor environment/JSON precedence now takes effect. The environment filter judges actual child-visible exports, including caller-local shadowing and Bash 5.2's export-cache rebuild, and keeps reserved helper names out of children. Unknown or different encodings use conservative secret-carrier removal, which can remove otherwise allowed variables containing a short secret. These changes are on by default in both environment modes. (#76, #93)

The shell filter requires Python 3.9+ on the system default PATH from /usr/bin/getconf PATH and /usr/bin/env -0. A Python available only on a custom PATH is insufficient; BUREAU_PYTHON does not override the snapshot interpreter. Missing trusted tooling or an invalid snapshot stops before the child with 24. See numeric and environment rules for bounds, precedence and measured overhead.

Repository CI now runs four ubuntu-latest shards and six macos-latest shards, with a 90-minute job limit. BUREAU_TEST_SHARD=i/n selects one balanced share; unset runs the full suite and bash tests/run.sh --list lists it. Portable fixture paths and two CI-only test fixes are included: the fixtures accept Git's newer fetch-error wording and ensure productive silence tests emit enough events. These CI changes require no adopter CI resync. (#93)

Merge gate CI check

The merge gate's CI check now judges only the newest check run per check name and app, ordered by started_at (fractional seconds and numeric offsets included) and then by id; a group with an unreadable time orders by id alone. An older failed or queued run no longer holds back a newer successful run of the same check. Only successful check runs and successful legacy statuses count toward agents.merge_min_required_checks; skipped and neutral runs never fail the head and never count. This changes by default: a head whose checks are all skipped, for example a draft pull request in a workflow that skips drafts, now waits with "only 0 completed check(s)" under the default minimum of 1, also after the CI start grace. Set merge_min_required_checks: 0 to let such heads pass. The "no check run and no status" line still needs a head with no check run and no status at all.

Spec admission, numbering and phase resume

A full configured spec cap now returns quiet wait 28, with holding issue identifiers and states. Under manual merge mode, Merge stops counting by default; Build Review still counts. Set agents.max_concurrent_include_merge: true to keep the earlier manual single-flight behavior. The existing ticket-cap default remains 0 (unlimited). Numbers are reserved per issue across fetched origin branches, local branches and worktrees sharing one Git directory; retries reuse them. The allocator lock waits at most 300 seconds by default, then returns 124 and routes back to Triage. Separate clones/hosts need separate coordination. (#77)

Successful specify, plan and tasks phases now commit their feature directory locally and record input and artifact fingerprints. Registered workers resume only a verified committed prefix; ordinary retries discard unfinished edits. Changed inputs or failed spec review start again at specify. Stale local feature branches fast-forward; divergent local/origin history holds with 25 and needs-human before model work. Fresh spec resets use origin/<repo.base_branch>; a verified checkpoint selects its recorded commit. There is still one final stage push. Checkpoint reuse is on by default, requires both commits and metadata, and ignores older checkpoint formats. (#79)

Every spec now needs a plain, column-0 Governance and security section with Decision: and Rationale: lines before its first code or HTML block; leading YAML front matter is allowed. Background spec review and app spec/spec_review completion enforce the shared structural check by default. Add or move this section in existing specs. Spec review still judges adequacy; specify/plan must leave measurements, probes, benchmarks and full test gates to implementation/QA. Customized Spec Kit templates and the constitution remain preserved. See spec resume and governance.

The source range also upgrades Spec Kit to pinned 1.2.2, checks helper content before repository-writing CLI calls, preserves active dual-host integration and requires exact feature-directory variables for existing-feature helpers. Resolve customized helpers before specify integration upgrade; see Spec Kit resync. This upgrade is required for the new allocator. (#75)

Preserved implement worktrees and outside gates

A worker preserved after provider/result failure 22 or quota 23 can retain a clean HEAD ahead of origin solely by verified clean two-parent base merges. This narrow reuse rule is on by default, uses the original worktree path and requires Git 2.38+ for merge-tree verification. Own commits, conflict resolutions, dirt, unknown legacy records, timeouts and interrupted runs do not qualify. The existing clean on-origin rule remains independent of base resolution. See merge-only retries. (#80)

Codex implement/QA gate recovery now requires same-attempt receipt identity and proof that the exact configured command failed or aborted in a real repository-root execution. A legacy SANDBOX_GATE: claim alone stays blocked. Typed gate holds share that proof rule; independent product, security and human holds survive outside green. The executor reserves one outside run per stage attempt/gate/HEAD, with at most one verified executor publication commit between receipt and rerun. QA reuses its final outside test phase. This stricter behavior is on by default; keep repo.test_command set to the full project gate. See outside-gate recovery. (#81)

Review convergence and ticket withdrawal

The default review severity floor is now BUG: validated MINOR and SKIP findings are deferred, and a required fix can be discharged only by an exact match to a nonblank deferred finding. Choose MINOR for stricter review. A new total-round limit defaults to max_review_cycles + 1 (four with the existing default); unresolved work at that limit blocks with 25, while genuine approval can finish. Fresh attempts reserve a round before paid calls, including attempts later interrupted or failed. Changed policy or legacy approval records require fresh review; unchanged approval reuse and gate polling consume no round. Security/build floors and BLOCK remain in force. (#84)

Background ticket state is now a cooperative kill switch by default. Configured Done stops with 0, configured cancelled/canceled/duplicate IDs with 26, and other inactive IDs with 25. A latched withdrawal prevents later refresh failure or reactivation from restarting that run. Providers finish their current call; subsequent ordinary publication and recovery stop. Implement's best-effort preservation push of commits already made still runs. Additional checkpoint refresh failures warn once and allow the authorized unit to continue; mandatory reads stay strict. App prepare/finish keeps its existing protocol. See withdrawal. (#85)

Optional conflict repair and silence detection

Declared generated outputs and verified append-only files can be resolved deterministically, with dependency preparation, regeneration, explicit outside tests and checkout rollback. Both strategy lists default to empty; legacy mechanical rules remain available. Optional model repair runs only when agents.conflict_resolver.enabled is true, after deterministic resolution, with one durable attempt per ticket/base by default (maximum two). It cannot edit outside the conflict set or stage its own changes. Both forms need explicit repo.test_command and writable external snapshot storage sized for ignored dependencies too. (#86, #90)

Unresolved rebase conflicts now roll back, hold for a human and return 17 even when model repair is disabled; the old fallback returned 0 or 25. Successful semantic repair during review is published normally and receives fresh review inputs. Rebase alone force-pushes with a lease pinned to the fetched issue SHA. Green repair creates no approval or reusable merge gate. See deterministic repair and model repair.

The provider silence watchdog is opt-in and defaults to 0 (off). Useful JSONL events reset its deadline; noise and CLI liveness do not. An optional longer child window requires an identified owned tool process. Silence drains owned writers, returns 25 with timeout_kind: silence and records a human hold after withdrawal checks. Review cancels and joins siblings before recording its partial paid round. Wall-clock timeout stays 124; independent cancellation stays 130. Owned-process cleanup also applies with the watchdog off. Test the installed CLI's streaming compatibility before enabling it. (#88)

File admission and continuous dispatch

The file-overlap gate is opt-in (agents.file_overlap_gate: false by default for standalone operations). When enabled, atomic reservations cover task paths and open Bureau PR diffs before Build and before writers, including app prepare/finish, Copy/QA and rework. Unknown scope is repository-wide, rename paths count on both sides, and generated docs/changelogs still overlap. Conflicts return quiet 29 without a paid pass, alert or human label. Waiting scope expansions retain the previous grant; reservations have no TTL and survive evidence pruning. (#87)

The tmux launchers now start one supervised continuous dispatcher in place of stage pollers. It requires explicit agents.file_overlap_gate: true even for one lane or dry-run; otherwise startup returns 24 before selection. After all writers are resynced, enable that gate before restarting a launcher. Dispatch defaults to two concurrent ticket lanes, drains downstream work first and refills when a lane finishes. The process-lane cap is separate from agents.max_concurrent_issues; existing batch execution retains default three when no shared value is configured. (#89)

Quiet admission, quota, transient service/authentication and pending merge-gate waits yield lanes. Human, unknown, terminal and intentional handoff outcomes persist in the skip store; reconcile the ticket, stop dispatch and remove its skip entry before retrying, clearing human holds too. Launch journals preserve outcomes across dispatcher loss; incomplete launches remain held. Owned stale/DIRTY Merge work can refresh the pinned base at most twice per lane and return to fresh Build Review through exit 20. This creates no merge success or reused approval. Stop/join cleanup signals only live owned runtime handles. Separate clones/hosts and older writers do not share this coordination. See dispatch and file admission.

Completion evidence, human briefs and local learning

Receipts, run manifests, gate digests and a stable waiting register are automatic. Successful provider receipts must persist before success is forwarded; other evidence writes are best effort. Recovery requires the same attempt and HEAD plus the unchanged original result. bureau-runtime.py waits shows open causes and the observed waiting share; missing historical end times remain null. The private evidence store has a global 16 MiB/4,096-file budget, including staging; completed runs rotate at 128 runs/30 days and open waits/active or interrupted runs are protected. Full protected storage can prevent success persistence and end the provider call with 22. (#78)

Existing human merge boundaries now automatically publish one acceptance brief per PR/HEAD to the ticket and PR, with independent retry status, immutable pointers and explicit missing evidence. A brief grants no acceptance or merge authority. Optional insights are normally empty and limited to three single-line observations of 280 characters per attempt. They stay local, with best-effort privacy filtering; malformed observations do not fail a stage. bureau-learnings drafts BUREAU-BACKLOG.proposed.md candidates for human triage. (#82)

Failed and held calls can also contribute insights. Shell-derived cause classes, metadata-only stage outcomes and review dispositions (applied, declined, skip, deferred) are collected automatically without a new switch. Each learning ledger keeps 2,048 rows/30 days on collection under the global evidence budget. Dispositions contain severity and a filtered repository-relative path; applied/declined remain model self-reports. Learning fields are removed from external comment projections and never change routing or rules. See evidence and privacy and failure learning. (#91)

Stage prompts now select unexpired, path-relevant LESSONS.md entries plus untagged general advice, with a default complete-context budget of 8192 UTF-8 bytes per stage. Spec and review use the bounded form; both implement loops and QA gain injection. Whole entries are retained in deterministic order and oversized entries are dropped. Existing free-form files need no migration and become one bounded general set; a legacy file that cannot fit is dropped whole too. Entry metadata keys paths, globs, tags, owner, expires (inclusive UTC date) and evidence are optional and unset by default; advice never authorizes work. Set a stage budget to 0 to disable it. (#92)

Derived architecture decisions, their template and index are under docs/adr. They retain their dated derivation and open disagreements; proposed status records the historical snapshot. They add no runtime behavior. (#83)

Upgrade an existing installation

From v3.4.1: stop all shepherds, pollers, dispatchers and supervisors, preserve unfinished work, and compare installed script drift before replacing anything. Select tag v3.5.0 in the source skill checkout and refresh skill discovery. Install/resync pinned Spec Kit 1.2.2 after resolving customized helpers, preserving the constitution and active integration. Resync the scripts and interfaces scopes as one set (--resync-interfaces --resync-scripts) in each adopting repository, resolving customization conflicts through preview and resolve. --update changes configuration only. See Upgrade to v3.5.

Before restart, choose the manual-Merge counting policy and review severity floor, check that repositories whose heads carry only skipped or neutral checks get a successful check or set merge_min_required_checks: 0, check active/cancellation state IDs and numeric settings, add/move governance in existing specs, and retain the shared number/checkpoint/admission/dispatch/repair records. Launcher users must explicitly enable overlap after every writer is updated. Silence and both configurable conflict strategies stay opt-in; do not enable them merely by copying an example. Restart drivers together, run doctor and qualify a representative ticket before unattended dispatch.

Mixed resync is incompatible: old shepherds treat 28 as a failure, and an old exit-2 spec stage with a new shepherd can still escalate to 13. Partial helper/schema/interface updates also break receipt/gate and provider-result contracts. Resyncing scripts cannot replace case statements already loaded in a running shell.

From earlier versions: follow Upgrade to v3.4.1 and its earlier sections first, then the v3.5 steps above. Existing approved specs should resume downstream; number reservations do not import older issue-directory associations. Inspect any pre-fix development evidence store or previously published unsafe learning text separately; resync does not scrub history.

Compatibility and rollback

Configuration schema versions and the app prepare/finish protocol remain compatible. New numeric exits require coordinated consumers. Bash 3.2+ remains supported; the shell snapshot filter has the system-PATH Python/env requirements above, and merge-only reuse needs Git 2.38+. Existing customized templates, project instructions and the Spec Kit constitution must be preserved. Local locks and rollback cannot protect separate clones/hosts, unrelated external writers, detached commands or writes through external symlinks.

To roll back, stop every driver, select tag v3.4.1 in the source skill checkout and restore its scripts and interfaces together or the private backup (rollback). Preview removal of new helpers and return Spec Kit assets to the saved compatible set; v3.4.1 expects Spec Kit 0.7.5. Restore earlier configuration, preserving the v3.5 coordination records separately for inspection. Disable the new launcher pool and reconcile leases, reservations and unfinished work before starting the older pollers. Old scripts cannot consume the v3.5 wait codes or coordinate its stores. Rollback cannot undo commits, pushes, published briefs or Linear/GitHub changes.

Known limitations

Live provider/event compatibility and representative installation acceptance remain pending. Evidence is local and best effort except for successful provider receipts; unusual process/filesystem failures can lose observations. Original provider files are required for completion recovery. The insight filter can miss private text or reject benign text, and brief delivery cannot guarantee exactly-once service publication. Bounded lessons and learning remain advisory. Strict CI/base/just-in-time merge gates and human merge authority still apply after every local green result.
