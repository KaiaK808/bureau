Bureau v3.9.0 — Semgrep and Trivy evidence, Python bytecode fix

Release preparation · 2026-11-20 · source tag v3.9.0. v3.9.0 is a minor release on v3.8.0. Tagging and GitHub Release publication remain separate maintainer operations.

The release includes #158, #159, #160 and #161 in first-parent merge order. All changes are merged. The changelog collects the four release fragments.

What changed since v3.8.0

Optional Semgrep CE evidence in code review

Independent specialists finish their first pass before all review roles receive the bounded Semgrep projection in the late step. Semgrep scans offline under network denial. Bureau loads the bundled bureau-semgrep-rules.yml from the installed runtime and reads any configured extra rules and .bureau/semgrep-ignore.json suppressions from the pinned PR base. Bureau verifies a private copy of the Semgrep packages against a shipped manifest before probing the interpreter and re-hashes the copy before each scan side. An empty set of eligible files passes as not_applicable before scanner prerequisites are checked.

Advisory mode reports and continues. Blocking mode holds approval on new findings at or above the configured severity and on unavailable or incomplete measurements. Existing BLOCK verdicts and review caps still apply. The blocking merge path rechecks the scan receipt against the head and base.

Optional Trivy evidence in QA

Trivy scans dependencies and configuration on the final QA head, including repositories without a test harness. This release excludes image scanning. The stage runs a verified private copy of the binary offline under network denial, checks the external database cache for integrity and freshness, and uses Trivy's embedded configuration checks. Database downloads occur in a separate operator refresh. Expiring exceptions come from the pinned base and the scan ignores head-native suppressions.

Advisory mode reports and continues. Blocking mode holds for a human on qualifying new findings, measurement gaps or coverage gaps without an active exception. After a failed base scan, unclassified head findings still count toward the severity floor, even if every coverage gap has a file exception. Blocking merge also requires a final-head receipt in repositories without a QA state.

Scanner receipts and merge freshness

Both scanners write immutable evidence attempts and add a retention reference for each PR that produces or reuses one. Open consuming PRs keep referenced attempts beyond the newest 20. An unknown PR inventory keeps all referenced attempts.

In blocking mode, the receipt check and last base fetch precede the existing just-in-time merge gates. A final read checks the PR base name and live branch tip before the head-pinned merge. If either changes, the merge retries with exit 2 even when the final gates pass. The ticket checkpoint remains the last step before merge.

Python bytecode in stage commits

Stages suppress installed Bureau helper bytecode and exclude the Bureau cache from shell stage commits. The installer adds the literal scripts/__pycache__/ ignore rule and preserves existing rules. Staging and doctor match the exact path components and existing aliases of the same directory. A separate application's Scripts/__pycache__/ remains eligible for ordinary staging on a case-sensitive filesystem.

Configuration and exit-code changes

Semgrep and Trivy are off until enabled. Set the appropriate enabled key to boolean true and select advisory for the first adoption. Blocking is a separate opt-in through mode. See Semgrep configuration and Trivy configuration.

Key Default / action Effect
review.semgrep.enabled, review.semgrep.mode false, advisory Enables offline Semgrep CE in code review. Blocking also rechecks before merge.
BUREAU_SEMGREP_VENV Operator-supplied venv or shared-state fallback Selects the pinned Semgrep environment for the matching platform and interpreter.
qa.trivy.enabled, qa.trivy.mode false, advisory Enables offline Trivy in QA. Blocking also rechecks before merge.
BUREAU_TRIVY_BIN, qa.trivy.cache_dir Operator-supplied binary or shared-state fallback, plus an external cache directory Supplies the pinned executable and its separately refreshed databases.
qa.trivy.image_archive_command Remove from existing configurations Runtime and doctor reject this key, including with null or with Trivy disabled.

A pre-staged Bureau cache refuses with the existing exit 24 and leaves the index untouched. See exit codes.

Upgrade an existing installation

From v3.8.0, once v3.9.0 is published. Stop every shepherd, queue loop, dispatcher and supervisor. Preserve unfinished work, local commits, customized assets, instructions, the Spec Kit constitution and shared runtime records. Compare installed script drift and reconcile local incident fixes before replacing assets. Select the published v3.9.0 tag, refresh discovery, preview and resolve conflicts, then resync the complete scripts scope in every adopting repository.

/bureau-init --resync-scripts --target both

Use $bureau-init in Codex and retain the installation's existing target selection. --update edits configuration only.

For Semgrep, create a standard-library venv with the supported CPython and install Semgrep CE 1.183.0 from the shipped wheel-only hash lock. Set BUREAU_SEMGREP_VENV or use the shared-state fallback. Qualify network isolation on the deployment host, then enable review.semgrep.enabled with review.semgrep.mode set to advisory. See Semgrep installation.

For Trivy, provide the verified 0.76.1 binary through BUREAU_TRIVY_BIN or the shared-state fallback. Select an absolute qa.trivy.cache_dir outside the repository and refresh it separately while it is empty or already Bureau-managed. Qualify host network isolation, then enable qa.trivy.enabled with qa.trivy.mode set to advisory. See Trivy installation and refresh.

In the resynced repository, run python3 scripts/bureau-doctor.py --mode background for a background installation or python3 scripts/bureau-doctor.py --mode app for an app-only installation. Reconcile holds. If doctor reports a tracked scripts/__pycache__/, run its printed cleanup command for the matched literal directories once and commit the removal. The ignore entry takes effect for untracked files. Restart all drivers together so they load the new scripts. See From v3.8.0 and tracked Python bytecode.

From earlier versions. Apply the migration guide's cumulative steps through v3.8 first. The v3.8.0 publication record itself needs only a source checkout update.

Scanner Shipped platform pins

For rollback, stop drivers and reconcile unfinished writers, local commits and holds. Known limitations

  • Real-engine validation of Semgrep's private-copy boundary, Linux isolation on deployment hosts and adopting-repository qualification remain pending.
  • The separate GitHub-hosted Ubuntu Trivy job remains pending after offline implementation. It needs network access to download the pinned archive and refresh a cache. It verifies the archive and extracted-binary hashes before refresh and qualifies filesystem flags under unshare. Pinned-engine flag behavior, platform isolation and adopter compatibility still need a networked CI or maintainer run.
  • Trivy reports reduced coverage for unrecognised lockfile forms or non-canonical manifest and lockfile names. In blocking mode, each affected file needs an active base coverage exception to waive its gap.
  • The writer of the historical adopter cache remains unknown.
  • The release branch's own macOS and remote suites, CI, tested refs and final tree comparisons remain TBD until the maintainer runs them.
