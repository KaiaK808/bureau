Bureau v3.4.0 — operator hooks without submodule recursion; Claude effort per stage and configuration directory

Stable release · 2026-10-09 · source tag v3.4.0. The GitHub Release is marked as latest and records the exact tagged commit. The previous stable release is v3.3.0, with its candidates v3.3.0-rc.2 and v3.3.0-rc.1. Earlier releases: v3.2.1, v3.2.0 and its candidate v3.2.0-rc.1, v3.1.0 with its candidates v3.1.0-rc.2 and v3.1.0-rc.1, v3.0.2, v3.0.1, v3.0.0 with its candidates v3.0.0-rc.2 and v3.0.0-rc.1, and the previous major release v2.0.0.

v3.4 is a minor release on v3.3.0 with six pull requests. The v3 exit-code contract stays; no exit code is new. It goes straight from v3.3.0 to stable, without a release candidate.

What changed since v3.3.0

Remote git and the environment of branch code (#69)

With the default and with repo.remote_git_runs_hooks: "operator", Bureau's push, fetch and pull no longer recurse into submodules. A repository whose stages change submodule commits must push those itself or set the key to true; Bureau's push neither pushes nor checks those commits in the restricted modes. Bureau forces push.recurseSubmodules=no, fetch.recurseSubmodules=no and submodule.recurse=false after the caller's git options, so configuration files, includes, environment entries, -c and --config-env cannot turn recursion back on. The default fetch previously recursed on demand into populated submodules.

In those modes, calls that ask for recursion, git clone and unknown leading git options are refused with 128 before git runs. This includes git submodule and any accepted prefix of --recurse-submodules, --recurse-submodules-default or --recursive, except a value of no; --no-recurse-submodules is allowed. Every subcommand argument is checked, including option values and words after --. --attr-source and --shallow-file now consume their separate value in every mode. No Bureau script clones or asks for recursion.

The new "operator" value runs only the main checkout's own hooks directory, hooks/ in the git common directory, with core.hooksPath forced to its absolute path even from a linked worktree. An operator pre-push, such as Git LFS or a secret scanner, can run while a tracked .githooks or .husky directory stays excluded. Hooks defined in configuration stay switched off by name. true keeps every configured hook; false or an absent key keeps hooks off. Doctor reports remote_git_hooks as on, operator or off, accepts "operator" without a type warning and warns when Git LFS uses that mode without an executable pre-push in the operator directory.

By default the agent's environment no longer carries BUREAU_ENV_FILE and BUREAU_CONFIG. The same applies to the review build check, the three QA test runs, repo.post_implement_command, the Codex completion test, the app test action, upstream-port.sh build/test commands and the Claude and Codex login checks. "clean" already dropped them. Bureau's own scripts, the provider process, git and gh keep the paths. Custom project commands that read them must locate their configuration themselves or receive what they need explicitly. The shell and Python filters stay in parity; see the security boundary.

Claude effort per stage (#65)

The resolved effort now reaches Claude as --effort <value>, including behind the Headroom wrap. Precedence is BUREAU_REASONING_<STAGE>, then agents.<stage>.reasoning_effort, then agents.providers.claude.reasoning_effort. Claude accepts low, medium, high, xhigh and max; none, minimal and ultra now cause configuration error 22 before any provider call. An existing Claude effort setting therefore changes the next run: previously it was resolved but never passed, leaving the operator's Claude settings in effect. Without a setting the argv stays as before and the CLI keeps its own default. Codex effort is unchanged, and --describe reports the resolved effort for both runners.

A clean preserved worktree can resume (#66)

A stage with a target branch can re-register an unregistered preserved worktree and continue when it is a linked worktree of this repository at its top level, outside the main checkout, with an empty git status --porcelain --untracked-files=all and HEAD equal to or behind origin/<branch> after a fresh fetch. Ignored files do not count. The single Re-accepted the clean preserved worktree … line names the head and origin branch. Uncommitted changes, untracked files, commits origin lacks, an unknown or missing origin branch and a failed fetch retain the refusal, exit 21, needs-human and the halt comment; spec always refuses. A stage that failed with unfinished work still preserves it and drops its disposable registration.

A Claude configuration directory for an installation (#67)

agents.providers.claude.config_dir or BUREAU_CLAUDE_CONFIG_DIR selects the CLAUDE_CONFIG_DIR given to the Claude child and its claude auth status --json check; the environment variable wins. This lets headless stages use a lean profile instead of the operator's global instructions, hooks, plugins and user-scope MCP servers. The path must be absolute or start with ~/, and the directory must exist; an invalid setting ends with 22 before any provider call. Unset, this setting leaves the inherited Claude directory unchanged. Codex ignores it. --describe reports config_dir, and doctor reports claude_config_dirs per enabled Claude stage and warns when Claude is not logged in in a configured directory. See Claude configuration directory.

Malformed environment names in the secret filter (#70)

An environment entry whose name is no shell identifier no longer runs code during secret filtering. On bash 3.2, an indirect expansion of such a name could execute its array subscript in the Bureau shell, which holds the unexported .env keys; glob characters could also expand into filenames. bureau_without_secrets, bureau_untrusted_env and bureau_exec_runtime now skip those names unexpanded. Characters that make a subscript or substitution are rejected under every locale; with the caller's nocasematch, some locales still accept a few non-ASCII letters, which execute nothing. Well-named variables are filtered as before. Exploitation required a malformed entry in the environment that starts Bureau, such as a tmux server's environment. No setting or exit code changes.

.env and the start line (#71)

Configuration and troubleshooting now state the existing precedence: an allowed key defined in an installation's .env overrides the process environment and the start line; a key absent from .env uses the environment value. For one run, use a per-stage key absent from .env, or change or comment out that line and restore it afterwards. This is a documentation correction with no behaviour change or resync of its own.

Upgrade an existing installation

From v3.3.0: select tag v3.4.0 in the source skill checkout, then resync the scripts scope as one set (--resync-scripts); bureau-config.sh, bureau-doctor.py, bureau-env.sh, bureau-provider.py, bureau-runtime.py and bureau-supervision.py changed together. Pause dispatch, preserve unfinished work and customized files, and use preview and resolve. No files under templates/ outside templates/scripts/ changed since v3.3.0, so no interfaces resync is needed. No configuration schema or data migration is needed; /bureau-init --update changes configuration only.

From older versions: go through Upgrade to v3.3 and its earlier upgrade sections first, including the scripts and interfaces scopes where required, then follow the v3.4 steps. The previous stable notes retain the v3.3 candidate upgrade paths.

What to check before dispatch resumes

  • Submodules: with the default and with "operator", Bureau's push, fetch and pull neither push nor fetch submodule commits, and the push does not check whether they are on the remote. If stages change submodule commits, push those yourself or set repo.remote_git_runs_hooks to true, which restores every configured hook as well as the previous recursion behaviour.
  • Project commands: check repo.test_command, scripts/bureau-test.sh, repo.post_implement_command and upstream_port build/test commands for reads of BUREAU_ENV_FILE or BUREAU_CONFIG. Those paths no longer reach branch code or the agent by default; make custom commands locate their configuration themselves or pass what they need explicitly.
  • Operator hooks: to keep an operator pre-push, such as Git LFS or a secret scanner, put an executable hook in the main checkout's own hooks directory (hooks/ in the git common directory, usually .git/hooks) and set repo.remote_git_runs_hooks to "operator". A tracked .githooks or .husky directory is excluded in that mode. Check doctor's remote_git_hooks and any Git LFS warning before the next push.
  • Claude effort: an existing reasoning_effort for a Claude stage now takes effect. Check agents.<stage>.reasoning_effort, agents.providers.claude.reasoning_effort and BUREAU_REASONING_<STAGE>; use low, medium, high, xhigh or max, or remove the setting to keep the CLI's default. none, minimal and ultra on a Claude stage now end the call with configuration error 22 before any provider call.
  • Claude configuration directory: the new setting is optional. To use it, create an absolute directory (or use a path starting with ~/), log in once with CLAUDE_CONFIG_DIR=<dir> claude, and set agents.providers.claude.config_dir or BUREAU_CLAUDE_CONFIG_DIR. The environment variable wins. Check doctor's claude_config_dirs login report for every enabled Claude stage; an unconfigured inherited directory is reported as logged_in: "not checked".
  • Start-line overrides: for a key the loader accepts and .env defines, .env wins over the process environment and the start line. A key absent from .env uses the environment value. For one run, use a per-stage key absent from .env, or change or comment out its .env line and restore it afterwards. BUREAU_REASONING_<STAGE> is read from the process environment; the .env loader does not accept it.
  • Preserved worktrees: the re-accept needs no configuration. For a worktree previously halted with 21, keep unfinished work intact, make the worktree clean and push its commits, then remove needs-human before its next pick. The spec stage and a worktree with uncommitted changes, untracked files or commits origin lacks still refuse with 21.

Restart queue loops and supervisors after resync so they read the new scripts: a loop sources bureau-config.sh once at startup, and a stage already running keeps the old scripts because the installer replaces files atomically. Run doctor (python3 scripts/bureau-doctor.py --mode background), check remote_git_hooks and the claude_config_dirs login report, and qualify a representative ticket before unattended dispatch resumes. Doctor's effective-settings report uses JSON and its process environment; it reads only BUREAU_RUNNER_IMPLEMENT from .env for the repo.test_command warning. See Upgrade to v3.4.

Compatibility and rollback

Dependencies, supported platforms, configuration schemas and the manifest version are unchanged. The v3 exit-code contract stays; no data migration is needed. Existing Claude effort settings now apply, and the default remote-git and branch-code environments change as described above.

To roll back, select tag v3.3.0 again in the source skill checkout and resync the scripts scope as one set, or restore the private backup (rollback). Restore prior configuration if you enabled the new options: v3.3.0 treats "operator" as hooks off and ignores the Claude config_dir and resolved effort settings. Check the prior Git LFS hook arrangement, then restart queue loops and supervisors. Rollback cannot undo commits, pushes or Linear/GitHub changes made in between.

Known limitations

  • With the default and with "operator", git clone is refused with 128 because the new repository's configured hooks cannot be listed beforehand; no Bureau script clones. In "operator" mode a command outside a repository runs with hooks off because there is no common hooks directory to select.
  • The remote-git switches cover hooks only. Filters, fsmonitor and credential helpers still run; a credential helper can see the GitHub tokens. Hooks first defined while a command runs, such as through a file a pull checks out, are outside the names listed beforehand; Bureau's stages run no pull.
  • A remote, refspec, pattern or option value spelled like a recursion option is refused with 128 too, even after --. A value of no and --no-recurse-submodules are allowed. This guards Bureau's own calls and does not sandbox other git invocations.
  • Under true, a hook that reads stdin inside a command substitution can block on some git versions after a push that recurses into submodules: git can start the superproject's hook with descriptor 0 closed, and the substitution then reads its own pipe. The fixture hooks read in their own shell to avoid that hang.
  • A malformed environment entry skipped by the shell secret filter reaches its child unchanged; its value is not checked for a secret. Well-named variables remain filtered.
  • On git 2.55 a configured hook named like an event can make the per-name switch an event switch, so "operator" also suppresses the operator hook for that event.
  • These controls do not isolate code running as the same Unix user. It can still read the operator's files and stored logins, find the main checkout through git rev-parse --git-common-dir, or write the operator hooks directory and configuration. Removing the paths hides only a .env or .bureau.json outside the default place. See SECURITY.md.
