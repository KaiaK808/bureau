Bureau v3.10.0 — Merge charter, inherited-profile doctor and commit secret scan

Release preparation · planned 2026-12-01 · source tag v3.10.0 once published. v3.10.0 is a minor release on v3.9.2. Tagging and publication remain separate maintainer operations; this document does not announce a published release.

The release includes #170, #171, #175, #174, #173, #176, #177, #179, #178, #181, #180, #182 and #183 in first-parent merge order. All content changes are merged. The changelog collects all 12 release fragments; #182 changes only a test timing row and has no fragment.

What changed since v3.9.2

Merge charter: trusted policy, enrollment, queue and exceptions

The new opt-in agents.merge_charter declares a strictly validated merge policy. A maintainer publishes sanitized policy on the actual default branch and explicitly enrolls the repository with bureau-charter.py enroll. Enrollment lives in the shared Git directory, so linked worktrees share it and independent clones do not. Installation and resync never enroll. Both merge gate passes use a pinned default-branch policy, fetched with hooks and submodule recursion disabled; PR-controlled configuration cannot disable enrollment. Enrolled policy errors, indeterminate enrollment and PR changes to .bureau.json require a human with exit 25. Doctor checks declarations, enrollment, locally fetched policy and digest drift without creating state or making remote reads.

For unenrolled repositories, a merge run adds exactly one local git rev-parse --is-bare-repository --show-toplevel --git-common-dir read from the working directory, with hooks disabled and inherited GIT_* overrides removed for that call only. Its unexported result is reused through status --common-dir at the initial probe and both gate passes. It adds no GitHub CLI or network calls. A failed lookup, bare repository or missing work tree blocks with charter-policy and 25; run the merge stage from a work tree and repair inaccessible enrollment before retrying.

Enrolled policy can require an approved Linear label or cycle and reserve exception classes by committed path or exact ticket label. A missing approval waits with 2; exceptions and indeterminate classification take precedence with 25. Classification covers deleted paths and both rename/copy endpoints, and requires complete non-shallow ancestry. Queue approval and exception labels share a complete ticket snapshot. Both merge routes compare the final live target tip with the classified target SHA, even with scanners or freshness checks off; movement retries with 2. This read precedes the ticket kill-switch checkpoint and the head-pinned merge. GitHub's merge operation has no expected-base option, so target observation and merge remain separate operations.

Doctor reports queue mode and exception classes. suite, red_main and report are validated declarations only: suite receipts, merge reports, main-CI latches and concurrency enforcement are outside this release. The queue and exception gates extend the earlier foundation fragment; they are active for enrolled repositories in the final combined release. See merge charter configuration.

Inherited Claude profile checks and auto-memory off

Every background Claude child gets CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 after environment filtering, even if the parent sets it to 0. The guard includes stage calls, review helpers, conflict and upstream helpers, login checks, CLI capability probes and Headroom launches. Interactive Claude outside Bureau is unchanged.

Doctor warns once about stages inheriting the operator profile and lists only user MCP server names and enabled-plugin names, with their source-file paths. Missing files mean empty lists; unreadable or invalid files produce explicit could not check warnings and unknown lists. Project/managed settings and plugin-provided servers are outside this inventory. Doctor remains read-only and does not persist a drift baseline. A lean agents.providers.claude.config_dir or overriding BUREAU_CLAUDE_CONFIG_DIR silences the inheritance warning and needs its own login. See Claude configuration directory.

Scan what the agent commits as a review floor

Code review always scans added committed lines between the pinned merge base and head for known credential formats and long high-entropy secret assignments. It reads Git objects without repository-controlled commands, external diff drivers, providers, scanner binaries or databases. There is no enable switch or Trivy prerequisite. Open findings and unavailable or malformed measurements prevent approval, including approval reuse; BLOCK survives and review caps still apply.

Findings mask detected values, paths and rule IDs after the complete scan, including later, suppressed and omitted detections. Scanner, redaction or locator exceptions discard partial output and return a blocking not-measured result without raw diagnostics. Each finding carries a pinned head blob ID and a 16-hex path fingerprint for resolving redacted paths; incompatible parser formats remain not measured. Proven deletions skip path budgets and blob reads. Narrow exceptions come only from the pinned base's .bureau/secret-exceptions.json and need an owner, reason and future expiry. This check does not scan intermediate history, decoded content, unchanged lines or commit messages; masking does not cover undetected values or arbitrary transformations. See committed secrets.

Acceptance contracts without enforcement

Optional version 1 declarations map Spec Kit requirement and task references to intended checks or human-reserved decisions. A standard-library offline CLI validates the closed schema, bounds and references; synthetic examples cover both forms. No stage, gate or prompt reads the contract and there is no enablement key. A well formed declaration proves neither completeness nor verifier existence, success or product acceptance. See the format and runnable examples.

Trusted merge publishers

Automatic merges now count only the newest visible review from a typed publisher in default-branch agents.merge_publishers, using complete snapshots, strict headers and same-node edit checks for every verdict. Missing or invalid policy holds automatic merging with 25. Doctor warns on absent policy in manual mode and rejects present invalid values in either mode. Publication failure stops review explicitly with 18; edited reviews need fresh Build Review with 20, and incomplete snapshots retry with 2. A dedicated Bureau App is preferred: a shared human or Actions principal trusts everyone acting as that identity. Deletion of a newer verdict without trace remains undetectable. Head and target safeguards remain in force. See trusted merge publishers.

Dormant shared test wrapper

bureau-test-wrapper.py supplies trusted literal argv policy, private child-start/end proof, a queue-aware budget clock, cancellation teardown and read-only doctor diagnostics. repo.test_wrapper is absent or empty by default, and repo.test_wrapper_start_timeout_seconds defaults to 21600 within (0, 86400]. The primitive rejects checkout-owned symlink traversal and distinguishes unavailable authority from invalid policy. Existing stage routing is not connected: configuring the wrapper changes no current launch, timer, build reuse key or evidence format. See test wrapper configuration.

Local suite serial reruns and timing data

The repository-only tests/run_suite.py waits for every shard before rerunning eligible failed files once, serially, within a five-file/3600-expected-second budget. Deadlines stay unchanged. Results are atomic, and a locked file-level flake ledger feeds a proposal outbox. A recovered green means an observed file-level flake, not a proven cause. Hosted CI and direct tests/run.sh calls never retry. External wrappers must keep exclusive suite/worktree admission, use a clean checkout, keep output and stable state outside the worktree, validate receipts and consume proposals. Detached processes outside the test group and persistent fixtures are not tracked. #182 records the measured charter queue driver duration for sharding. See local full-suite operation.

Dispatcher shutdown lease settlement and process-control limits

After joining direct lane children, dispatcher cancellation observes its launched runs during one shared five-second settlement wait. It ends with settled ownership or a best-effort human_hold diagnostic naming each unresolved run and issue. Uncertain leases remain retained; unrelated groups are never signalled. Diagnostic write/flush failures preserve cancellation exit 130, including at interpreter shutdown. Existing nested shutdown grace periods remain unchanged.

Process-control regressions use bounded 30-second startup, exit and recovery waits on loaded runners, and clean up the recorded child group before removing temporary files. Production inspection remains fail-closed with its two-second timeout; diagnostics add a short cause without raw process output. BUREAU_TEST_DISPATCH_SETTLE_SECONDS and BUREAU_TEST_PROCESS_INSPECT_SECONDS are bounded test-only overrides, not operator tuning keys. No configuration or store migration is required.

Security reporting and the v3.9.2 publication record

The security policy supports the latest published tag, lands fixes on main for the next tagged release and directs reports to GitHub private vulnerability reporting. Branch examples use generic issue keys. These documentation changes need no adopter action.

The v3.9.2 publication record preserves its tag, merge commit, release review rounds, first-pass gate suites, CI history including cancelled main runs and the passing tag run, and tested-tree comparison. It needs only a source checkout update. See the unchanged archived v3.9.2 notes and validation record; these are historical facts, not v3.10.0 validation.

Compatibility and rollback

Configuration schema versions 1 and 2, Spec Kit 1.2.2 and the current-workspace prepare/finish protocol remain supported. The existing scanner platform constraints remain in the v3.9.0 compatibility record. The secret scan adds no external scanner requirement. Enrolled classification requires full history; corrupt nested bare repositories without HEAD remain unsupported worktree inputs. Target observation is not atomic with merge.

For rollback, stop all drivers and reconcile unfinished writers, local commits and holds. Follow the restore procedure to restore the complete v3.9.2 asset set, compatible configuration and installer records from the private backup. Explicitly unenroll with the trusted new helper before reverting an enrolled installation to a runtime without charter enforcement. Retain shared runtime, scan and enrollment evidence for inspection; do not delete leases to clear a hold. Rollback does not undo commits, pushes, comments, labels or state moves.

Known limitations

  • Charter gates are a local accident guard. Manual merges, independent clones and deliberate bypass with the same user permissions are outside it; final target observation and merge are separate operations.
  • Charter suite receipts, reports, red-main latches and concurrency enforcement are not implemented. Acceptance contracts validate declarations only, and test wrapper stage routing is dormant.
  • Shared publisher identities trust everyone acting as that principal, and deletion of a newer verdict without trace is undetectable.
  • The committed-secret scan covers literal added physical lines within its bounds, not complete history or decoded/split secrets; unmeasured scans block approval. Masking is limited to detected values and specified rule-masked forms.
  • Doctor inventories user-profile names only and persists no drift baseline. Live profiles/providers, services, scanner behavior and adopting installations remain unqualified by these offline records.
  • Local serial recovery is an observed file-level flake, not a cause diagnosis; external admission and receipt validation remain required.
