Configuration reference

Every knob bureau-init exposes — what it controls, where it lives, and what the default is. Two surfaces:

  • .bureau.json — written by /bureau-init to the target repo's root. Normally gitignored. UUIDs + agent toggles; trusted merge policies require an explicitly published, sanitized default-branch copy.
  • Environment variables — runtime settings read by the pipeline scripts, set inline (BUREAU_DRY_RUN=1 ./scripts/queue-loop.sh ...), exported in the operator's shell or read from the installation's .env.

The pipeline scripts select the installation's secrets file in this order: a non-empty process BUREAU_ENV_FILE, otherwise repo.env_file in .bureau.json, otherwise .env next to .bureau.json. A relative process override counts from that JSON file's directory, without resolving a config symlink; repo.env_file must be an absolute path or start with ~/, expanded with the invoking user's home. An invalid repo.env_file, or a missing file selected by it, refuses with exit 24, never falling back to the checkout's .env; doctor reports an error. New installations use ~/.config/bureau/<repository directory name>.env, with directory mode 0700 and file mode 0600; existing installations keep their adjacent .env until moved. For a key accepted by the loader and defined in that file, the file wins over the process environment, including values exported in the operator's shell or set on the start line. For a key the file does not define, the environment value is used. Keys outside the loader's allow-list are ignored.

Moving secrets outside the checkout blocks the conventional checkout .env path only. The path is hidden from the agent's environment, but a process with the user's permissions that searches for the file, reads .bureau.json or inspects Bureau's own processes can still find and read it. A real read block needs an operating-system sandbox, which this release does not have. Doctor warns when the resolved real path is inside the main checkout (including subdirectories) or when the file is readable by group or others; it never executes or prints the file's contents. See move an existing installation.

For one run, use a per-stage key that .env does not define, or change or comment out the corresponding line in .env for that run and restore it afterwards. See the per-stage overrides below for the available keys and an example.

Setup captures the project-specific settings. Verify credentials, installed tools and real tests before running work. Current app tasks use the app-selected model; provider settings below select background CLIs.

design.impeccable

Impeccable is optional local tooling. Omission or enabled: false preserves the existing UX, implement and review prompts and checks. Setup defaults to:

{
  "design": {
    "impeccable": {
      "enabled": false,
      "skill_version": "4.9.0",
      "engine_version": "0.1.23"
    }
  }
}

Set enabled: true only after the operator places the pinned skill and engine. Optional skill_path names the skill directory containing SKILL.md, reference/ and scripts/; relative paths resolve from .bureau.json, absolute paths and a symlink to the skill directory are supported. Without it, Bureau checks .claude/skills/impeccable, then .agents/skills/impeccable. The engine defaults to scripts/bin/<os>-<arch>/impeccable inside that skill; an operator's IMPECCABLE_BIN may select another binary with the same verified platform digest. macOS and Linux on arm64/x64 are supported.

Bureau installs nothing from Impeccable. The operator can use a checkout or install it separately with impeccable install --project --providers=claude --no-hooks -y. --no-hooks is required. That installer downloads an unversioned bundle, so operators must install and verify the pinned skill 4.9.0 and engine 0.1.23; upstream skill 4.9.1 and engine 0.1.24 are not supported by this release. It can install four Claude agents even with hooks disabled: remove or disable those agents separately, and do not enable its hooks. Bureau never installs or enables these hooks or agents, and stages do not use them. An npm package version alone does not pin the skill bundle. No third-party playbooks, references or binaries are vendored here, so no Apache-2.0 redistribution notice is added.

The asset installer and bureau_install.py check verify the operator's local installation without executing it. bureau-impeccable-pins.json records the supported versions and skill-tree digest. The digest hashes a UTF-8 manifest sorted by POSIX relative path, each row path<TAB>sha256(file bytes)<LF>. It includes every regular file except .git, .git/ and scripts/bin/; nested symlinks are rejected. The engine is hashed separately against the matching version/platform row in the skill's shipped scripts/engine-checksums.txt, which is itself covered by the tree digest. Missing files, changed content and unsupported pins report unavailable with a reason; setup and stages continue without treating that as a clean measurement. New upstream versions require new maintainer-reviewed pins; changing only the configured versions cannot bypass verification.

UI tickets carry needs-ux (or the configured linear.labels.needs_ux.name) or have a spec design.md. Other tickets retain their existing behavior. For eligible tickets:

  • UX references the installed shape, critique, craft-floor, init and document Markdown paths. It reads root PRODUCT.md and DESIGN.md, creates missing documents using that guidance, preserves existing content and records project-rule overrides in DESIGN.md. Project rules win over floor defaults and bans. Unresolved decisions use the existing human-hold contract. These two root documents are permitted alongside the spec artifacts.
  • Implementation uses the bounded iteration loop, including when use_goal_loop is configured, so Bureau can check each returned pass. It scans changed .html, .css, .scss, .sass, .less, .tsx, .jsx, .vue, .svelte, .astro, .ts and .js files against origin/main, including untracked UI files. Mechanical feedback covers quality findings plus gradient text, glow rules, oversized headings and extreme tracking. The full deferred tier runs at attempted completion and after the last pass/post-implement hook. Identical source and ignore bytes reuse that attempt's full result; changed bytes require a fresh scan. Findings feed the next implementation pass. Unresolved findings at the cap remain draft and require a human to resume, with FIXES_NEEDED feedback carried in the summary. The final check also catches generated UI changes from the post-implement hook.
  • Review finishes and saves all three independent specialist judgements first. Only then does Bureau scan changed UI files from the pinned PR head and archive impeccable.json with the review artifacts. A separate late step lets each specialist assess findings as machine evidence against the pinned source and project rules. Additional findings and holds are combined with the original judgements; the late step cannot delete them. Machine warnings do not automatically determine review severity. Opted-in UI reviews do not reuse an earlier approval, because local tooling and ignores can have changed.

Every engine invocation sets both DO_NOT_TRACK=1 and IMPECCABLE_NO_TELEMETRY=1, sets IMPECCABLE_BIN to the verified binary, and executes that binary directly with detect --json --no-config and local file paths. Bureau uses private source snapshots, never URLs, Chrome scans, live, install, update or check. No launcher fallback or network is needed. Each detector run has a 30-second timeout; timeout cleanup kills and joins its process group. Exit 1, other execution errors and malformed JSON are not measured, never clean. A verified detector's failed measurement holds implementation; unavailable optional tooling is reported without failing the stage. Review includes unavailable/not-measured status in its evidence and comment, without inventing findings. No changed UI files is not applicable, not a clean scan.

Native project, local and inline detector ignores are bypassed. Bureau accepts only the repository's .impeccable/bureau-ignore.json array with an exact file, one antipattern and a named nonempty reason:

[
  {"file": "src/brand.css", "antipattern": "overused-font", "reason": "Approved brand typography in DESIGN.md"}
]

Directory/glob/rule-wide ignores, missing reasons and extra keys are rejected as not measured. Accepted ignores retain their reason in machine evidence. This bypasses native design-system context too; project-specific design rules remain the specialists' responsibility. Static detection cannot establish visual quality or replace rendered accessibility and interaction checks.

Upgrade: compare installed script drift, resync the complete scripts scope (including both helpers and the pin file), and restart drivers together. When design.impeccable.enabled is true, install the pinned skill 4.9.0 and engine 0.1.23 as above, then set design.impeccable.skill_version to "4.9.0" and design.impeccable.engine_version to "0.1.23" in .bureau.json together with the scripts resync, or remove both keys to follow the pins. Until the local tooling and configuration match the pins, Bureau reports Impeccable as unavailable and stages continue without it. With Impeccable off, only the resync is needed: setup writes the new defaults, and an existing .bureau.json with old version values and enabled: false is unaffected. Fake-detector tests require no downloads; an optional real-engine test runs only with IMPECCABLE_BIN set and checks the operator-supplied local binary. Live provider and adopting-repository qualification remains an operator check.

The operator prepares a dedicated venv for Semgrep 1.183.0. To use a custom path, set BUREAU_SEMGREP_VENV in the setup shell and in the environment that starts Bureau's drivers. For example, export BUREAU_SEMGREP_VENV="$HOME/.local/share/bureau/semgrep/venv". With the variable unset, Bureau uses <shared Git directory>/bureau/tools/semgrep/venv. Run these commands from the adopting repository root and choose the interpreter assignment for your platform.

semgrep_python=python3.14  # macOS arm64
# semgrep_python=python3.12  # Linux x86_64
semgrep_venv="${BUREAU_SEMGREP_VENV:-}"
if [ -z "$semgrep_venv" ]; then
  semgrep_common_dir=$(git rev-parse --git-common-dir) &&
    semgrep_common_dir=$(CDPATH= cd -- "$semgrep_common_dir" && pwd -P) &&
    semgrep_venv="$semgrep_common_dir/bureau/tools/semgrep/venv"
fi &&
  "$semgrep_python" -m venv --without-pip "$semgrep_venv" &&
  "$semgrep_venv/bin/python" -B -c 'import platform; print(platform.python_implementation(), platform.python_version(), platform.machine())'

Confirm CPython 3.14.x arm64 on macOS or CPython 3.12.x x86_64 on Linux. Install the locked wheels with uv pip install --python "$semgrep_venv/bin/python" --require-hashes --only-binary :all: -r scripts/bureau-semgrep-lock.txt.

Do not create it with uv venv or virtualenv: both add _virtualenv.pth and _virtualenv.py to site-packages, and verification rejects every file the manifest does not list. Bureau also needs a reviewed bureau-semgrep-manifest-<os>-<arch>-cp<major><minor>.json beside the runtime scripts that matches the venv's interpreter. Because some dependencies are compiled, every CPython minor needs its own manifest. This release ships darwin-arm64-cp314 and linux-x86_64-cp312. With any other interpreter, an enabled scan with eligible files reports unavailable and names the missing manifest. Advisory review treats unavailable scanner results, including those caused by a missing venv or a missing or mismatched manifest, as evidence. There is no configurable version or manifest override.

Maintainers generate a universal wheel-only lock for semgrep==1.183.0 with uv pip compile --universal --generate-hashes --only-binary :all:. After selecting the complete wheel set for one OS, architecture and CPython minor, run python3 scripts/semgrep_pin.py WHEEL_DIRECTORY --os linux --arch x86_64 --python cp312 in the Bureau source repository. The generator refuses any wheel hash absent from the lock. It hashes the payload files inside the locked wheels, maps purelib/platlib payloads to site-packages and refuses unsupported installation schemes or path collisions. Review the lock, manifest and tool compatibility together before shipping them. The maintainer script is not installed in adopting repositories.

Once per measurement, Bureau copies site-packages into a private runtime under the run's mkdtemp directory (mode 0700). Every component from the operator venv root through lib/python3.<minor>/site-packages must be a real directory, checked with lstat. All entries inside must be regular files or real directories, including excluded entries. Bureau anchors traversal to directory descriptors, opens source files with O_NOFOLLOW and hashes the same reads it writes into the copy, preserving only the executable bit (files 0700 or 0600, directories 0700). It compares the copied file set, including semgrep-core, with the manifest before the interpreter probe, then re-hashes the private copy before each scan side. Changed, missing or additional files in the copy make the tool unavailable. Later changes to the original site-packages tree leave the copied package bytes intact. Install metadata inside *.dist-info (RECORD, INSTALLER, direct_url.json, REQUESTED and uv's uv_cache.json) and adjacent __pycache__ directories are excluded from copied files and manifest comparison. The operator venv must contain exactly one lib/python3.<minor>/site-packages directory. Its minor and the selected manifest's platform must match the interpreter probe. The resolved interpreter is a trusted dependency outside the package snapshot and manifest.

The -I -S interpreter probe and both scan sides share one private shadow venv per measurement. Bureau writes home = <base interpreter directory> and include-system-site-packages = false as the two lines of the shadow's pyvenv.cfg. The shadow's bin contains only python, a symlink to the resolved real path of the operator venv's bin/python. The resolved path must be an absolute regular executable file. In a venv created with --copies, it can reside inside the operator venv, where replacing the executable after the package copy can affect the scan. The shadow's lib/python3.<minor>/site-packages is the verified private copy, a real directory preserving the package layout, including semgrep/bin/libs for resource-based core discovery. Bureau invokes Python through the shadow symlink and uses the shadow's generated settings. Each call uses -I -B -X pycache_prefix=<fresh directory>. The probe additionally uses -S. Operator Semgrep launchers, executable-adjacent fallback helpers, system site-packages and adjacent bytecode are excluded from execution.

Every scan and interpreter probe receives exactly PATH=/usr/bin:/bin, private HOME, XDG_CONFIG_HOME, XDG_CACHE_HOME and TMPDIR, plus LANG=C.UTF-8, TZ=UTC, PYTHONDONTWRITEBYTECODE=1, SEMGREP_SEND_METRICS=off, SEMGREP_ENABLE_VERSION_CHECK=0 and DO_NOT_TRACK=1. The operator venv's bin directory is excluded from PATH, and helpers resolving beside sys.executable see only the shadow's python. Bureau invokes the interpreter by its absolute shadow path. Provider keys, Bureau secrets, GitHub tokens and other Semgrep settings do not pass through. Runtime network denial is required for eligible scans. Linux uses a probed unshare -rn user/network namespace and macOS uses sandbox-exec with the shipped bureau-scan-nonet.sb profile denying network*. If isolation cannot run, the status is not_measured, with reason network isolation unavailable. Bureau never falls back to an online scan.

The scan uses private snapshots of changed Python, JavaScript and TypeScript files at pinned base and head, with explicit file lists. Bash remains covered by ShellCheck and shell boundary tests. Native .semgrepignore, .semgrep.yml, .semgrep.yaml and .semgrep/ configuration is excluded and recorded in the snapshot manifest; git ignores and inline nosemgrep are disabled. --no-rewrite-rule-ids keeps authored rule IDs stable across private snapshot paths, so exact suppressions match. Only Bureau-authored rules ship, under Bureau's license; no Registry packs or engine binaries are vendored. The separately installed LGPL-2.1 engine runs as a separate program.

Only new occurrences count toward the floor. Identity is rule ID, file and SHA-256 of matched lines with surrounding whitespace, including a trailing CR, stripped per line. Snapshot bytes are split only at LF (\n), matching Semgrep's physical lines; vertical tabs and Unicode line separators inside comments cannot shift finding identities. Finding bounds are checked against that physical line count. If a count rises from N to M, the surplus is new and the projection lists every head occurrence with that count note. Editing other lines leaves an existing finding existing; moving it to another file makes it new. Base-only suppressions require an exact file and rule ID with a named, nonempty reason:

[
  {"file": "src/legacy.py", "rule_id": "bureau.python.os-command", "reason": "Approved legacy maintenance boundary"}
]

A suppression added by the PR cannot suppress that PR. Wildcards and reasonless suppressions fail measurement. The receipt distinguishes findings_new, findings_existing and findings_suppressed.

Semgrep emits measured, not_measured, unavailable and not_applicable. The shared receipt format also defines reduced_coverage for other scanners. Every status other than measured names a reason. A measured result requires exit 0, valid JSON, no errors and coverage of every explicit target. Scan timeouts, scanner execution or output errors, and incomplete target coverage yield not_measured. Bureau loads the rules and validates the base suppressions before building the snapshots. A configured extra_rules file missing from the pinned base yields not_measured even when neither side has eligible files. After the policy checks succeed, an empty eligible set on both sides yields not_applicable and passes blocking mode without checking the venv, isolation, interpreter or runtime manifest, or starting any scanner or probe. Its receipt still binds the version, lock hash and hashes of the shipped manifest files. The projection shows the actual status.

In advisory mode, Bureau reports Semgrep evidence and skips the scanner's verdict floor. On a fresh review, any Semgrep projection, including not_applicable, triggers one late provider call per specialist after the three independent passes complete, even with Impeccable disabled. Malformed supplemental output stops the review stage with exit 22. In blocking mode, new findings at the configured severity or higher, not-measured results and unavailable tooling lower APPROVE to REQUEST_CHANGES after the build fold and before the existing cycle/round caps. BLOCK stays BLOCK. The caps still escalate unresolved work for a human.

Reports and receipts live in write-once attempts under <state dir>/scans/semgrep/<identity digest>/<UTC timestamp-random suffix>/. report.json retains raw tool JSON and snapshot metadata; receipt.json binds head, base, pin, settings and policy digests and the report hash; projection.json holds at most 20 findings with tool, rule ID, file, line, severity and count note. Matched source is never projected into comments. Receipt digests join the existing evidence archive. Every PR that produces or reuses an attempt adds an exclusively created refs/pr-<number> file under the retention lock, without rewriting the receipt; receipt validation ignores this reference directory. Retention keeps the newest 20 attempts per repository/tool plus any attempt referenced by at least one open PR, including a replacement PR reusing evidence from a closed PR; an unreadable PR inventory conservatively keeps all referenced attempts. Legacy receipts also retain their original pr reference.

Pin, settings and policy digests join approval reuse identity, independently of build-check reuse. The pin identity includes the private-copy execution boundary, so receipts and approvals from earlier operator-linked runtimes are not reused. Bureau prepares the merge message before scanning. Before the existing just-in-time merge gate recheck, blocking mode reads the PR head and current base ref/commit and runs Semgrep with receipt reuse for those inputs. After the scan, Bureau fetches the scanned base ref once more, requires its commit to equal the scanned base, and checks the current PR head and base ref name. This freshness check runs before applying blocking findings, unavailable tooling, failed measurements or receipt failures: changed inputs abort with the gate-regression report and retryable outcome (2), so the next tick measures the current inputs. An unchanged blocking result refuses merge with the existing blocked outcome (25). Semgrep gate marks bind to the scanned head, including when it differs from the initial gate's head.

After the just-in-time gates pass, Bureau makes one GraphQL read of the PR's base branch and its live baseRef.target.oid tip. If the branch differs from the approved Target, Bureau returns to Build Review with exit 20. A failed read or a difference from the scanned head, base branch or base commit retries with exit 2. Bureau then checks the ticket kill switch immediately before merging with --match-head-commit set to the scanned head, followed by the post-merge result read. The live tip catches base advancement after the last fetch even when the final gates passed against a newer base. Blocking mode completes all fetches and merge-message preparation before the final gates. The approval binding and final target check apply in every scanner mode.

Before a pin is reviewed, select a release at least two weeks old and newer than every published advisory fix, verify its checksums file and both release archives against their Sigstore bundles, compare archive hashes to that verified checksums file, and hash the extracted regular trivy binary separately. For this pin the expected keyless identity and issuer are exact, including the release tag:

identity='https://github.com/aquasecurity/trivy/.github/workflows/reusable-release.yaml@refs/tags/v0.76.1'
issuer='https://token.actions.githubusercontent.com'
cosign verify-blob \
  --bundle trivy_0.76.1_checksums.txt.sigstore.json \
  --certificate-identity "$identity" --certificate-oidc-issuer "$issuer" \
  trivy_0.76.1_checksums.txt
for archive in trivy_0.76.1_Linux-64bit.tar.gz trivy_0.76.1_macOS-ARM64.tar.gz; do
  cosign verify-blob --bundle "$archive.sigstore.json" \
    --certificate-identity "$identity" --certificate-oidc-issuer "$issuer" "$archive"
  shasum -a 256 "$archive"
done

Compare those archive hashes with trivy_0.76.1_checksums.txt before extraction, then record each extracted binary's SHA-256 and byte size in the pin file alongside the archive name/hash, version, release date, signing identity and issuer. Verify all of these in the pin review; a version string alone is never an execution trust anchor. The shipped pin was maintainer-verified through that procedure. Neither the signature assets nor scanner binaries are vendored.

Bureau re-hashes the private binary before each execution. Changes to the operator path after the copy have no effect.

The refresh destination must be empty or a Bureau-managed cache, outside the repository. Refresh first verifies and privately copies the pinned binary, downloads into a fresh private directory using --download-db-only and optionally --download-java-db-only, with --disable-telemetry --skip-version-check, then replaces the operator cache only after successful metadata/content checks. A failed download leaves the previous cache intact. bureau-trivy-cache.json records Version, UpdatedAt, NextUpdate and DownloadedAt per database, every cache file's hash, and the digest of that complete file inventory, including any external checks bundle. Scans copy and hash the same reads and require agreement with the record and database metadata. The freshness check uses each database's UpdatedAt. Measurement fails if that timestamp is more than max_db_age_hours old or more than one hour ahead of the current time. A changed cache is not_measured. Downloading old data again cannot make it fresh. Unreadable or non-regular cache inputs also fail measurement.

The scan cache retains only db/ and optional java-db/; all external checks bundles and other cache content are removed. Misconfiguration checks therefore come from the pinned binary's embedded bundle, whose identity is the binary digest. The snapshot manifest records removals. Before each filesystem scan, Bureau re-checks the private database bytes and discards non-database cache content again.

Every scanner execution, including refresh, receives exactly PATH=/usr/bin:/bin, private HOME, XDG_CONFIG_HOME, XDG_CACHE_HOME and TMPDIR, plus LANG=C.UTF-8, TZ=UTC and PYTHONDONTWRITEBYTECODE=1. No caller TRIVY_*, provider secret, GitHub token or Docker connection setting passes through. Every scan runs under runtime network denial using probed unshare -rn on Linux or sandbox-exec with bureau-scan-nonet.sb denying network* on macOS. If isolation fails, scans report not_measured with reason network isolation unavailable. The refresh CLI is the sole networked scanner operation and is absent from the shell stage helper's allowed commands.

All release-dependent flags live in bureau-trivy.py's FLAGS table. Filesystem scans use --offline-scan --skip-db-update --skip-java-db-update --skip-check-update --skip-vex-repo-update --skip-version-check --disable-telemetry, explicit empty Bureau --config and --ignorefile, a private --cache-dir, --scanners vuln,misconfig, --format json --output, and --timeout 5m. Filesystem scans run from a separate private working directory against snapshots of the pinned base and final head. Native trivy.yaml, trivy.yml, .trivyignore, .trivyignore.yaml and .trivyignore.yml files are removed throughout both snapshots.

IaC trivy:ignore: neutralization strips trailing ignore comments only from small, explicitly recognised shapes whose preceding bytes are fully classified. YAML accepts comment-only lines and simple scalar mappings or sequence entries, using boundary # outside single-line quoted or allow-listed plain scalars; double quotes use backslash escapes and single quotes escape a quote by doubling it. HCL and Terraform accept literal assignments and simple block delimiters with #, // or same-line trailing /* ... */; Bicep accepts literal declarations and object properties with // or same-line trailing /* ... */. Dockerfiles accept only whole-line # comments with optional leading whitespace before any heredoc. JSON has no comments and is never stripped. A .template file selects JSON when its first non-whitespace byte is {, otherwise YAML. Every other shape is kept and reduces coverage when it contains a marker; HTML-style comments are unsupported. Every byte outside a removed comment, including whitespace and LF/CRLF line endings, is preserved; paths and removed-comment line numbers are projected. This neutralization does not depend on an engine flag.

Stripping and inventory share one classification of the original, unstripped snapshot bytes. Unrecognised marker lines stay byte-identical and produce reduced_coverage, naming the file with reason inline ignore format not recognised. This includes YAML anchors, aliases or tags (&, *, ! in node position), block scalar indicators, flow collections, HCL interpolation or heredocs, Bicep multi-line strings, and every construct outside the recognised shapes. For YAML, HCL and Bicep, the classifier does not try to recover context after a line falls outside the recognised shapes: all later marker lines in that file are retained too. In Dockerfiles, any << makes that line and every later marker line uncertain, including after an apparent closing delimiter; quoted, dashed and dotted delimiter syntax is deliberately not parsed. Lines without markers still establish this conservative context. Markers known to be data also stay unchanged and reduce coverage: for example a JSON string, password: secret#trivy:ignore:X in YAML, a quoted literal, an unsupported comment form, or # trivy:ignore:X inside a Dockerfile instruction. Any retained marker could still be interpreted as an ignore by Trivy.

Before checking the binary, cache or isolation, Bureau inventories both snapshots. If neither has eligible inputs, the result is not_applicable, with no scanner or probe execution. V1 checks npm package manifests with package-lock/npm-shrinkwrap, pnpm or Yarn locks; requirements*.txt; PEP 621/Poetry dependencies with uv/Poetry locks; Go module/sum files; Dockerfiles, Compose files and Terraform files. Manifest and lockfile discovery is case-insensitive, but non-canonical filename case (for example PACKAGE.JSON, Package-Lock.json, REQUIREMENTS.TXT or PyProject.toml) reduces coverage with reason non-canonical inventory filename case and names the file, on both case-sensitive and case-insensitive filesystems. Missing locks, requirements that are not exactly pinned, absent result targets and direct dependency names missing from lock roots reduce coverage and name the affected file/package. Every inventoried lockfile requires a matching result target, including go.sum; engines that omit a target reduce coverage rather than silently accepting an alias. Direct-name consistency for Go and ecosystems outside the JS/Python set is explicitly reported as unchecked. Version ranges are not compared in v1. Snapshot blobs are limited to 32 MiB per file and base policy to 1 MB; oversized inputs fail measurement. Other recognized ecosystem inputs are scanned and reported as having unchecked lockfile consistency. A base measurement failure produces reduced_coverage, reason base not measured, and head findings stay unclassified rather than being counted as new; their severities still enforce the blocking floor as new findings would, even when coverage exceptions waive every file's coverage gap.

Lockfile consistency fails closed: the handwritten parsers accept only recognised tool-written forms, and unsupported syntax anywhere in a parsed file produces reduced_coverage, with the file named and reason lockfile format not recognised, never a clean measurement. This also holds in blocking mode, where an unexcepted coverage gap blocks. Locks are validated even without a matching manifest. Both the parser policy and the neutralization version are part of receipt identity. Earlier receipts are remeasured once under the new identity; subsequent eligible clean receipts can be reused normally. pnpm requires two-space indentation steps, no tabs or level jumps, plain or quoted mapping keys and no flow syntax in importers; only direct keys in the root importer's dependencies, devDependencies and optionalDependencies maps count. Apart from its reserved __metadata map, Yarn requires complete comma-separated selector headers ending at their final colon, without # or trailing text; comments must be whole top-level lines. Indented Yarn bodies are validated too: recognised Yarn v1 key/value lines and Berry mappings, scalar values and nested metadata retain full coverage, using two-space indentation without tabs, level jumps or children beneath scalars. Plain values use an explicit character and leading-form allow-list for tool-written versions and compact ranges, protocol references such as npm:, file:, link:, patch: and workspace:, Git/HTTPS URLs, hashes/checksums, booleans, cache keys, bin paths and platform conditions. Everything outside that allow-list reduces coverage, including values starting with ?, @, %, &, *, !, |, > or a backtick, and values containing : or #. Quoted scalars retain their existing handling. Recognised resolved URLs, integrity hashes, dependencies and optionalDependencies, checksum, languageName, linkType, dependenciesMeta, peerDependenciesMeta, conditions, bin maps, quoted scoped keys and CRLF files retain full coverage. Unsupported body syntax reduces coverage just like an unsupported header; body dependency names never count as selectors. JSON manifests and npm locks use the JSON parser, and npm lock root names come only from those three dependency maps in packages['']. Python 3.11+ uses tomllib; the conservative Python 3.9/3.10 fallback requires bare table components such as [project.optional-dependencies] and bare assignment keys, rejecting spaces inside table names, quoted keys and dotted inline keys. Only [project] treats dynamic as metadata; an optional-dependency group named dynamic contributes declared dependency names. Requirements accept exact pins, extras and whole-line or whitespace-prefixed inline comments; environment markers, line continuations and options such as -r, -c, -e and --hash are not recognised and reduce coverage rather than supplying or hiding names.

Vulnerability identity is (Target, VulnerabilityID, PkgName, InstalledVersion). Misconfiguration identity is (Target, ID, CauseMetadata.Resource, SHA-256 of normalized cause lines); bytes are split on LF only and whitespace is stripped per line. When Resource is missing, the cause-lines hash carries that part of identity and the projection names the affected check/file. Only checks with status FAIL count. File-level checks that the pinned release reports without cause lines (for example DS-0026, a Dockerfile without HEALTHCHECK) use a fixed file-level marker in place of the cause-lines hash and are projected with line 0. Newness is occurrence-aware: if an identity's head count exceeds its base count, only the surplus is new. Moving a vulnerable package to another manifest, changing its installed version or introducing another unsafe resource creates a distinct occurrence. Matched source, descriptions and raw scanner diagnostics never enter comments.

Once the scan step runs, advisory mode reports the result and QA continues. If PR lookup or base fetch fails while pinning the scan base, QA exits 18 before scanning, including in repositories without a test harness. Blocking mode holds on new findings at or above block_severity, not_measured, unavailable, or reduced_coverage without an active base coverage exception for every affected file. Coverage exceptions waive only the named file's coverage gap and never suppress qualifying findings, including unclassified head findings after a failed base scan. not_applicable passes as explicitly not applicable. No unavailable, unmeasured or reduced result is described as clean. A blocking QA result keeps the ticket in QA with needs-human and exit 25.

QA measures immediately before routing, after its commit, push and local checks. With Trivy enabled, live QA without a test harness runs git push origin HEAD even when there is no QA merge to publish. A rejected push exits 18 before Trivy evidence or ticket routing, including in advisory mode. The receipt binds the head actually handed onward.

With Trivy enabled in blocking mode, Bureau's automatic merge pipeline requires a valid, non-blocking receipt for the final PR head and pinned base, including when no QA state exists. It measures those inputs when it cannot reuse a matching receipt. With no QA state and agents.merge_mode: "manual", a human can merge without a Trivy receipt. When both scanners are enabled in blocking mode, their measurements must use the same inputs. Changed inputs or a failed read retry with exit 2. The live branch target is used because the PR's stored base OID can lag the branch tip. Merge charter foundation

The charter is off by default. An unenrolled merge run adds one local git rev-parse --is-bare-repository --show-toplevel --git-common-dir read to locate enrollment from the working directory, with no additional GitHub CLI or network calls, charter files or policy gates. This also applies when the declaration is omitted or has enabled: false. An enabled block alone activates no gate: enrollment is an explicit maintainer operation outside the checkout, never a side effect of installation, migration or scripts resync. Doctor validates explicit declarations even while disabled.

{
  "agents": {
    "merge_charter": {
      "enabled": false,
      "approved_queue": null,
      "exceptions": [],
      "suite": null,
      "red_main": null,
      "report": false
    }
  }
}

Unknown keys and wrong types are errors. enabled and report accept JSON booleans only. approved_queue is null or exactly one of {"label":"approved-for-merge"} and {"cycle_id":"12345678-1234-1234-1234-123456789abc"}; the label is an exact, nonempty Linear label name, the cycle is a UUID, and both together are invalid. exceptions is an array of objects such as {"class":"security","paths":["auth/**"],"labels":["security-sensitive"]}. Each class must be nonempty and unique, and each entry needs at least one nonempty path or label selector. Labels and class names are case-sensitive, without surrounding whitespace or control characters; repeated selectors are invalid.

Paths are root-relative and case-sensitive. Declared glob syntax is * within a component, ** across components and ? for one character within a component. A complete **/ component may match zero directories: **/tokens?.json matches both tokens1.json and src/tokens1.json. Absolute paths, drive prefixes, home prefixes, backslashes, empty/dot/traversal components, negation, brackets and brace expansion are rejected. Suite inputs and workflow paths are literal files, without globs. suite is null or {"id":"full","command":"bash scripts/check.sh","definition_files":["scripts/check.sh"]}; all three fields are required and strings must be nonempty single lines. definition_files is a nonempty array of unique paths. red_main is null or {"workflows":[".github/workflows/ci.yml"],"poll_seconds":60,"timeout_seconds":3600}; workflows is a nonempty array of unique literal .github/workflows/*.yml or .yaml paths. Timing values default to 60 and 3600 and must be positive integers with poll at most timeout. report: true requires both suite and red-main declarations. Suite receipts, reports, main-CI watching and latches remain declarations; those gates are not implemented.

For an enrolled repository, a label queue and two exception classes can be configured as follows. To select a cycle instead, replace the entire approved_queue object with {"cycle_id":"12345678-1234-1234-1234-123456789abc"}. A null queue adds no queue requirement; an empty exception list is allowed and retains the mandatory charter-policy exception.

{
  "agents": {
    "merge_charter": {
      "enabled": true,
      "approved_queue": {"label": "approved-for-merge"},
      "exceptions": [
        {"class": "security", "paths": ["auth/**", "**/tokens?.json"], "labels": ["security-sensitive"]},
        {"class": "data", "paths": ["migrations/**"], "labels": ["schema-change"]}
      ]
    }
  }
}

Each initial and just-in-time evaluation reads one validated Linear ticket snapshot when queue approval or exception labels need it. Queue labels are ticket labels, independent of PR labels. Cycle mode requests cycle { id } in that same snapshot. A missing approval label, an unassigned or different cycle, or an approval-only read failure waits with charter-queue, exit 2, and no merge. The read uses the existing Linear helper with one transport attempt and reloads the configured secrets file through Bureau's safe reader; missing fields, GraphQL errors, an unexpected ticket, unreadable JSON or pageInfo.hasNextPage: true never count as an empty label list. If exception labels depend on that failed or incomplete read, the result is class unclassified (charter-unclassified), exit 25, and human handoff. Approval cannot waive an exception.

Exception selectors come exclusively from trusted policy at D. The evaluator pins PR head H and the live target branch tip B, fetches and verifies both commits, requires a non-shallow repository and walks both histories to their roots before accepting exactly one merge base. It then classifies the complete NUL-delimited git diff --name-status -z --find-renames <merge-base(B,H)> H -- output. Copy detection is also enabled, including unchanged sources. Deleted paths and both rename/copy endpoints participate; a renamed-away protected path still requires a human. Shallow history anywhere in the repository, including a fetched comparison range, requires class unclassified and 25; restore complete history before retrying. Missing ancestry, traversal or merge-base warnings, diff warnings, object/fetch failures, ambiguous merge bases, malformed or truncated change records and undecodable paths also require unclassified and 25. Working-tree changes are never classification inputs. A path match or an exact ticket-label match holds with charter-exception, exit 25, names every matching configured class and requires a maintainer to inspect and merge. Exceptions dominate queue waits and stale-approval re-review. Both merge paths execute these same gates, in addition to all existing requirements.

The just-in-time evaluation retains the exact target SHA B used for classification. After the final gates, one live baseRef.target.oid read must still equal B; an advance, rewind or unreadable target retries with charter-retry and exit 2 before merging. Target comparison is the last gate before the ticket kill-switch checkpoint and head-pinned merge call. This check applies to every enrolled merge, including when blocking scanners are off or merge_require_up_to_date is false. The existing --match-head-commit still pins H. GitHub provides an atomic expected-head precondition; the target check remains a separate API read because the merge call has no expected-base option.

Call slots are reserved atomically before paid work; token/time limits can overshoot by already admitted concurrent calls. Existing stage timeouts still apply.

Progress is a separate opt-in policy. A turn is one completed background work stage (exit 0 or completed red build 14); wrappers and individual specialists do not add turns. Changing the contract requires fresh gate evidence.

Deterministic conflict resolution

repo.conflict_resolution.generated defaults to []. Each entry requires globs (nonempty array of repository-relative output patterns) and command (nonempty argument array, executed directly from the checkout root). Patterns are root-anchored: *, ? and character classes match one path component; ** spans zero or more components. repo.conflict_resolution.append_only_paths defaults to [] and contains exact repository-relative filenames, including root files such as CHANGELOG.md. Absolute paths, traversal and overlapping strategies are refused. No configuration migration is required; existing installations retain the legacy rules.

For Bureau's generated manual, cover every output of the renderer, which requires Pandoc:

{
  "repo": {
    "test_command": "bash tests/run.sh",
    "conflict_resolution": {
      "generated": [
        {"globs": ["docs/site/*.html"], "command": ["python3", "scripts/render_docs.py"]}
      ],
      "append_only_paths": ["CHANGELOG.md"]
    }
  }
}

A configured repair requires an explicit repo.test_command containing a command; whitespace-only or comment-only strings decline, and there is no inferred fallback. Append-only means verified insertions anywhere, including under Unreleased. Rewrites, deletions, binary input, missing base/side blobs, mode changes, unterminated input and ambiguous repeated nonblank base anchors decline. Concurrent insertions sharing any nonblank inserted line also decline, including identical new headings or context: preserving side sequences alone cannot prove section associations. New ATX/Setext Markdown headings in either insertion also decline, since they could capture entries from the other side. After source conflicts resolve, restore_worktree_deps prepares Node dependencies against the merged manifests using the package-manager rules before any generator or check; preparation failure declines the repair. All configured generators then run in declaration order, each limited to its own full output set. Generator or check failure, unavailable commands (including Pandoc), undeclared edits or remaining conflict markers restore the saved clean checkout and use existing conflict exit 17. Rollback restores only paths changed since the snapshot and grants directory/parent access only when needed. Unchanged ignored content and modes stay untouched. A filesystem failure on one path does not stop other restores or the saved-index/Git reset attempt; incomplete restoration declines explicitly. Saved directory modes are restored after the reset. Commands run outside the provider sandbox under repo.untrusted_env, with a fixed 1,800-second limit per command. Checks must leave the tracked tree/index unchanged and create no nonignored untracked files; ignored test caches are permitted. See the transaction contract for rollback and ownership limits.

Node repositories

restore_worktree_deps detects the lockfile beside package.json after a disposable worker's checkout/merge. npm retains its existing package-lock.json path: clone matching main-checkout dependencies or stage npm ci --ignore-scripts --no-audit --no-fund, then mount atomically. pnpm (pnpm-lock.yaml) and Yarn Classic 1.x (yarn.lock) install directly in the worker so relative workspace package links resolve there. They never clone or symlink the main checkout's node_modules; leave it out of repo.worktree_links.

pnpm runs pnpm install --frozen-lockfile --offline --ignore-scripts --prefer-offline --ignore-pnpmfile. Yarn Classic runs yarn install --frozen-lockfile --offline --ignore-scripts --non-interactive with YARN_IGNORE_PATH=1. Both set COREPACK_ENABLE_NETWORK=0 and disable Corepack download prompts. Numeric runtime settings

The shell consumers validate the numeric settings below after their source has been selected, including values inherited from the process environment. Accepted text contains only ASCII digits, at most ten characters, within the documented range. Leading zeros are decimal (010 becomes 10). An empty, signed, expression-like, oversized or out-of-range value uses the documented default and emits one warning line naming the key, never the rejected value. An absent setting (or a JSON null) silently uses its default. Zero is accepted only where the range includes it, such as disabling workbench panes or the in-flight cap.

The .env reader and precedence are unchanged: an accepted file entry replaces the inherited value; a rejected entry leaves it alone. The reader still rejects leading-zero text such as 010 for the keys on its numeric list, so use 10 in .env; inherited 010 and digit strings in JSON are normalized at consumption. Valid long budgets such as 5400 seconds per pass and 10800 seconds total retain their meaning. The existing Linear retry/request and merge-gate readers keep their documented source fallback and coercion rules.

queue-loop.sh validates its positional polling interval using the same 1–10080 minute range and 30 minute fallback. It exports BUREAU_QUEUE_POLL_SECONDS for the merge-gate picker; inherited values of that internal setting accept 1–604800 whole seconds and fall back to 1800 seconds when invalid. Without that override the picker uses agents.poll_interval_minutes.

The usage-signal fields pct (integer part, 0–100), reset_epoch and updated_epoch (whole seconds, 0–9999999999) are checked before shell arithmetic; invalid fields fall back to 0 with a warning naming the field. Fractional percentages keep their existing integer-part comparison. The already bounded shepherd merge wait/poll settings retain their base-10 and upper-cap behavior; their warnings now omit the rejected value.

Implementation results accept tasks_done from 0 through 100000 per pass; invalid counts contribute 0. The shared schema states this range in its field description because Claude rejects numeric minimum/maximum constraints; the shell enforces it for both providers. Alert-throttle log timestamps are checked before subtraction; a malformed record leaves its event unsuppressed. Counts and timestamps obtained from tools are also checked before shell arithmetic or numeric comparisons.

The shell environment filter reserves its own helper names (listed in _BUREAU_ENV_INTERNAL_NAMES in scripts/bureau-env.sh), including IFS and the _beb_*, _bec_*, _beh_* and wrapper locals in that list. Those exact names are removed from child environments and cannot be reintroduced through wrapper NAME=VALUE arguments. Other application variables keep the existing default/clean-mode rules.

Carrier checks read literal NUL-delimited names and values from /usr/bin/env -0, so an enclosing function's local variable cannot hide an exported secret carrier. Generic application names such as rc are not reserved. An isolated Python helper makes the per-entry decisions and returns only names to remove, or the allowed clean-mode entries. Bash validates the complete decision frame before decoding it; local secret values travel on stdin, never command-line arguments. Both transports use pipes, without a temporary file or here-string.

The snapshot interpreter is resolved once when bureau-env.sh is sourced, using only the system default PATH from /usr/bin/getconf PATH, with Bash's command hash cleared in the resolving subshell. It must resolve to an absolute path to an executable file. The helper uses that path with -I; a caller's PATH, hashed python3, shell function or virtualenv cannot replace it and receive the stdin secrets. Install Python 3.9+ on that system default PATH; having Python only on a custom shell PATH is insufficient. This restriction applies to the snapshot helper; other runtime tools retain their existing lookup rules.

The six-character embedded-secret threshold applies only when Bash's effective encoding and the helper's encoding are provably the same: their resolved nonempty CODESET names or locale identities must match. A matching character-probe length is insufficient; SJIS and GB2312 can count the same probe identically and a secret differently. Bash's highest-priority nonempty LC_ALL, LC_CTYPE or LANG binding supplies its locale identity; an empty declared binding may hide a still-active outer locale and makes that identity unknown. When the identities/codesets differ or cannot be established, every nonempty secret is removed anywhere inside another variable, regardless of length, for visible and hidden secrets alike. This can remove unrelated values containing a short secret, including allowed clean-mode variables. Exact copies are always removed.

With proven equivalence, the existing threshold is unchanged: visible secret copies use Bash's measured lengths, hidden exports use the actual exported locale and libc multibyte counting (UTF-8 uses surrogate-preserving decoding), and invalid bytes count individually. Thus a five-character UTF-8 secret such as äääää stays embedded in an otherwise allowed value, including clean-mode TZ, when the codesets match. The helper starts under C so older system Pythons can initialize even with an empty CODESET; the original exported locale comes from the snapshot. CODESET names are compared as identities, never used as Python codecs, so empty or unrecognized names cannot raise LookupError.

Measured snapshot-filter overhead on macOS is approximately 70–80 ms per wrapped call with system Python 3.9, versus 30 ms with Homebrew Python, across 20–1000 environment entries in default and clean modes. These are local measurements, not a performance guarantee; 100 calls can add roughly 7–8 seconds with system Python. The snapshot resolver currently follows the system default PATH described above; BUREAU_PYTHON does not override it. The Homebrew figure is a comparison measurement, not a change to the trusted interpreter selection.

No trusted interpreter, producer/helper failures, pipe failures and incomplete or malformed snapshot/decision frames stop before the wrapped child starts with 24 (environment-blocked). This holds for both environment modes and the curl scrub, including if and || callers, with or without set -e. Failure exits the calling shell; inside a subshell it ends only that subshell. The curl subshell scrub also refuses with 24 when a malformed host-variable name cannot safely be unset in Bash; the other wrappers remove it literally with env -u. The shell helpers support Bash 3.2 (including POSIX-mode sourcing) and require Python 3.9+ and /usr/bin/env with -0 (as on the supported macOS/Linux CI hosts). Snapshot ingestion does not require a writable temporary directory.

An uncertain result, including a failed merge acknowledgement, is reconciled with one fresh read; a still-uncertain result gets the same human hold.

An edited selected review of any verdict, a missing, malformed or duplicate binding line, or a binding that names a different head or target requires fresh Build Review. Bureau rereads that same node's identity, author, body, creation time and lastEditedAt for every verdict, including BLOCK, to detect changes between reads. An unreadable or deleted selected node never falls back to an older approval. The gate moves the ticket to Build Review and returns 20 with a refreshed report containing an approval_binding line. Inline review fetches the PR's advertised head commit, including a fork's same-named branch, and retains that reviewed head separately from the checkout after cleanup for the acceptance brief. Stale cleanup fetches the current PR head and discards local review output in the disposable worker, even if the branch and its tracking ref were deleted. If the fetch fails, cleanup uses the pinned review base and returns quiet retry 2 without needs-human, never a cached tracking head. Bureau deduplicates the gate comment when it can read earlier comments. If that lookup fails, it still hands back the ticket and posts the reason, which may repeat an earlier comment.

Only a merge-forward reported with base_refresh uses one of the dispatcher's two base refreshes per lane. A shepherd run allows agents.max_review_rounds stale-approval handoffs, counted after confirming the move to Build Review so a delayed Linear response cannot spend the allowance twice. If another approval goes stale during the run, the gate returns the ticket to Build Review and the shepherd sets needs-human and exits 25.

Comment and thread snapshots require complete pagination, stable counts, unique IDs and advancing cursors, bounded to 100 pages and a 90-second deadline per snapshot (each API call at most 30 seconds). Legacy status snapshots also require complete, count-consistent pages. API/GraphQL errors, partial data, null slots, unreadable bodies and review-shaped entries with unknown authors hold with 2; unrelated readable discussion with a null author is ignored. A complete history without an authorised verdict, or a valid BLOCK or REQUEST_CHANGES, holds with 25 and names agents.merge_publishers. Bureau authenticates the newest visible review in complete gate snapshots. Deleting a newer verdict without trace cannot be detected and may expose an older approval.

For ordinary gate refusals, a definitive blocker such as a failing CI check or a conflict the rebase agent cannot resolve takes precedence over failed reads in the same pass and returns 25. If the snapshot lacks a base branch name, the gate still checks the PR state, merge status and labels. Binding and merge-forward require a readable base branch. A pass with only undecided blockers returns 2, as does a failed final base read after both passes cleared.

Risk tier

The acceptance brief includes a mechanical low, normal or high tier and the counts/paths supporting it. The tier changes no routing, holds, verdicts or merges; a human merges every PR. It does not enable automatic merging or change agents.merge_mode. Omitting agents.risk_tier uses these defaults:

{
  "agents": {
    "risk_tier": {
      "low_max_changed_lines": 100,
      "low_max_files": 5,
      "high_min_changed_lines": 1000,
      "docs_patterns": ["docs/*", "**/docs/*", "*.md", "*.rst"],
      "test_patterns": ["tests/*", "**/tests/*", "test/*", "**/test/*", "test_*.py", "*_test.py", "*.test.*", "*.spec.*"],
      "sensitive_patterns": []
    }
  }
}

Changed lines means insertions plus deletions in base..HEAD. Low requires at least one changed path, every path matching the docs/tests lists, at most 100 changed lines and 5 files, no binary files and no sensitive path. High wins whenever a sensitive path matches or changed lines reach 1000. Normal covers everything else, including missing diff metadata (which is stated explicitly). Threshold comparisons are inclusive. Renames count as delete/add; binary files count as files with no inferred line count.

Globs use case-sensitive shell-style matching against repository-relative paths; * can cross /. A slashless glob also matches any basename. Docs/tests lists replace their defaults. sensitive_patterns adds to these mandatory defaults; an empty list cannot remove them:

Evidence is automatic and needs no .bureau.json key or configuration-version change. <git common dir>/bureau/evidence/v1/ holds private (directories 0700, files 0600) metadata-only receipts, background manifests, gate digests and waits. It retains no log bytes, excerpts, command text, ticket descriptions or structured-result prose. Original provider files/transcripts remain pointers outside the store; receipt recovery needs the unchanged original and its matching digest. Linked worktrees share the locked store; separate clones/hosts do not.

Completed runs expire after 128 evictable runs or 30 days, deleting each manifest with its receipts. Resolved waits and inactive ticket observations expire after 30 days. A global 16 MiB/4,096 file budget includes atomic staging and abandoned temporary files and evicts oldest completed data first; active/interrupted runs, open waits and runs referenced by open waits are protected. Replacements reserve their full new size and one additional file slot, so even unchanged/shrinking optional updates can be refused. Optional write/housekeeping exceptions warn/skip; a success receipt that cannot fit prevents success forwarding. An already oversized store with protected or undeletable files requires operator inspection. Each tick/queue iteration attempts up to four open-wait tickets within a shared 10-second network budget, including manual-mode repositories with merge/rebase disabled. Persisted oldest-first cursors take priority when an unchanged cursor can be written and read back with enough staging room for the next timestamp. Only refused persistence selects in-memory rotation; fresh shell ticks seed it in configured poll-interval buckets. For a stable set of N readable tickets, an advancing clock and at least one read started per sweep, all are attempted within N sweeps with writable cursors; the refused-write fallback has the same bound in a retained dispatcher or independent ticks at the configured cadence (default 30 minutes). Other restart/cadence patterns have no cross-process fallback bound; see stage protocol. Exact end times require Linear completion history or PR mergedAt; other resolutions retain null event times.
