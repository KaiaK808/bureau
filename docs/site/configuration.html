Configuration reference

Every knob bureau-init exposes — what it controls, where it lives, and what the default is. Two surfaces:

  • .bureau.json — written by /bureau-init to the target repo's root. Gitignored. UUIDs + agent toggles.
  • Environment variables — runtime settings read by the pipeline scripts, set inline (BUREAU_DRY_RUN=1 ./scripts/queue-loop.sh ...), exported in the operator's shell or read from the installation's .env.

The pipeline scripts select the installation's secrets file in this order: a non-empty process BUREAU_ENV_FILE, otherwise repo.env_file in .bureau.json, otherwise .env next to .bureau.json. A relative process override counts from that JSON file's directory, without resolving a config symlink; repo.env_file must be an absolute path or start with ~/, expanded with the invoking user's home. An invalid repo.env_file, or a missing file selected by it, refuses with exit 24, never falling back to the checkout's .env; doctor reports an error. New installations use ~/.config/bureau/<repository directory name>.env, with directory mode 0700 and file mode 0600; existing installations keep their adjacent .env until moved. For a key accepted by the loader and defined in that file, the file wins over the process environment, including values exported in the operator's shell or set on the start line. For a key the file does not define, the environment value is used. Keys outside the loader's allow-list are ignored.

Moving secrets outside the checkout blocks the conventional checkout .env path only. The path is hidden from the agent's environment, but a process with the user's permissions that searches for the file, reads .bureau.json or inspects Bureau's own processes can still find and read it. A real read block needs an operating-system sandbox, which this release does not have. Doctor warns when the resolved real path is inside the main checkout (including subdirectories) or when the file is readable by group or others; it never executes or prints the file's contents. See move an existing installation.

For one run, use a per-stage key that .env does not define, or change or comment out the corresponding line in .env for that run and restore it afterwards. See the per-stage overrides below for the available keys and an example.

Setup captures the project-specific settings. Verify credentials, installed tools and real tests before running work. Current app tasks use the app-selected model; provider settings below select background CLIs.

design.impeccable

Impeccable is optional local tooling. Omission or enabled: false preserves the existing UX, implement and review prompts and checks. Setup defaults to:

{
  "design": {
    "impeccable": {
      "enabled": false,
      "skill_version": "4.9.0",
      "engine_version": "0.1.23"
    }
  }
}

Set enabled: true only after the operator places the pinned skill and engine. Optional skill_path names the skill directory containing SKILL.md, reference/ and scripts/; relative paths resolve from .bureau.json, absolute paths and a symlink to the skill directory are supported. Without it, Bureau checks .claude/skills/impeccable, then .agents/skills/impeccable. The engine defaults to scripts/bin/<os>-<arch>/impeccable inside that skill; an operator's IMPECCABLE_BIN may select another binary with the same verified platform digest. macOS and Linux on arm64/x64 are supported.

Bureau installs nothing from Impeccable. The operator can use a checkout or install it separately with impeccable install --project --providers=claude --no-hooks -y. --no-hooks is required. That installer downloads an unversioned bundle, so operators must install and verify the pinned skill 4.9.0 and engine 0.1.23; upstream skill 4.9.1 and engine 0.1.24 are not supported by this release. It can install four Claude agents even with hooks disabled: remove or disable those agents separately, and do not enable its hooks. Bureau never installs or enables these hooks or agents, and stages do not use them. An npm package version alone does not pin the skill bundle. No third-party playbooks, references or binaries are vendored here, so no Apache-2.0 redistribution notice is added.

The asset installer and bureau_install.py check verify the operator's local installation without executing it. bureau-impeccable-pins.json records the supported versions and skill-tree digest. The digest hashes a UTF-8 manifest sorted by POSIX relative path, each row path<TAB>sha256(file bytes)<LF>. It includes every regular file except .git, .git/ and scripts/bin/; nested symlinks are rejected. The engine is hashed separately against the matching version/platform row in the skill's shipped scripts/engine-checksums.txt, which is itself covered by the tree digest. Missing files, changed content and unsupported pins report unavailable with a reason; setup and stages continue without treating that as a clean measurement. New upstream versions require new maintainer-reviewed pins; changing only the configured versions cannot bypass verification.

UI tickets carry needs-ux (or the configured linear.labels.needs_ux.name) or have a spec design.md. Other tickets retain their existing behavior. For eligible tickets:

  • UX references the installed shape, critique, craft-floor, init and document Markdown paths. It reads root PRODUCT.md and DESIGN.md, creates missing documents using that guidance, preserves existing content and records project-rule overrides in DESIGN.md. Project rules win over floor defaults and bans. Unresolved decisions use the existing human-hold contract. These two root documents are permitted alongside the spec artifacts.
  • Implementation uses the bounded iteration loop, including when use_goal_loop is configured, so Bureau can check each returned pass. It scans changed .html, .css, .scss, .sass, .less, .tsx, .jsx, .vue, .svelte, .astro, .ts and .js files against origin/main, including untracked UI files. Mechanical feedback covers quality findings plus gradient text, glow rules, oversized headings and extreme tracking. The full deferred tier runs at attempted completion and after the last pass/post-implement hook. Identical source and ignore bytes reuse that attempt's full result; changed bytes require a fresh scan. Findings feed the next implementation pass. Unresolved findings at the cap remain draft and require a human to resume, with FIXES_NEEDED feedback carried in the summary. The final check also catches generated UI changes from the post-implement hook.
  • Review finishes and saves all three independent specialist judgements first. Only then does Bureau scan changed UI files from the pinned PR head and archive impeccable.json with the review artifacts. A separate late step lets each specialist assess findings as machine evidence against the pinned source and project rules. Additional findings and holds are combined with the original judgements; the late step cannot delete them. Machine warnings do not automatically determine review severity. Opted-in UI reviews do not reuse an earlier approval, because local tooling and ignores can have changed.

Every engine invocation sets both DO_NOT_TRACK=1 and IMPECCABLE_NO_TELEMETRY=1, sets IMPECCABLE_BIN to the verified binary, and executes that binary directly with detect --json --no-config and local file paths. Bureau uses private source snapshots, never URLs, Chrome scans, live, install, update or check. No launcher fallback or network is needed. Each detector run has a 30-second timeout; timeout cleanup kills and joins its process group. Exit 1, other execution errors and malformed JSON are not measured, never clean. A verified detector's failed measurement holds implementation; unavailable optional tooling is reported without failing the stage. Review includes unavailable/not-measured status in its evidence and comment, without inventing findings. No changed UI files is not applicable, not a clean scan.

Native project, local and inline detector ignores are bypassed. Bureau accepts only the repository's .impeccable/bureau-ignore.json array with an exact file, one antipattern and a named nonempty reason:

[
  {"file": "src/brand.css", "antipattern": "overused-font", "reason": "Approved brand typography in DESIGN.md"}
]

Directory/glob/rule-wide ignores, missing reasons and extra keys are rejected as not measured. Accepted ignores retain their reason in machine evidence. This bypasses native design-system context too; project-specific design rules remain the specialists' responsibility. Static detection cannot establish visual quality or replace rendered accessibility and interaction checks.

Upgrade: compare installed script drift, resync the complete scripts scope (including both helpers and the pin file), and restart drivers together. When design.impeccable.enabled is true, install the pinned skill 4.9.0 and engine 0.1.23 as above, then set design.impeccable.skill_version to "4.9.0" and design.impeccable.engine_version to "0.1.23" in .bureau.json together with the scripts resync, or remove both keys to follow the pins. Until the local tooling and configuration match the pins, Bureau reports Impeccable as unavailable and stages continue without it. With Impeccable off, only the resync is needed: setup writes the new defaults, and an existing .bureau.json with old version values and enabled: false is unaffected. Fake-detector tests require no downloads; an optional real-engine test runs only with IMPECCABLE_BIN set and checks the operator-supplied local binary. Live provider and adopting-repository qualification remains an operator check.

Each dimension is independently optional; absent/null/0 disables it. Wrong types, unknown keys, negative/nonfinite limits or invalid contracts refuse execution with 24. Tokens/calls require integers; wall seconds may be fractional. Auth/help probes, deterministic shell checks and conflict-resolution validation receipts are not paid provider attempts; only identities admitted through the ticket ledger count. Wall time sums provider intervals, including concurrent calls, excluding idle queue time. Tokens include input/output plus Claude's disjoint cache-read/cache-creation input. Codex cached input is already included in input tokens. Every required counter must be reported; otherwise the attempt and aggregate token total stay unknown. Every valid reported counter still contributes to the known lower bound. Accounting is independent of session.cost_tracking.

allow_unknown_usage: true explicitly permits unreported tokens, retaining null totals and enforcing the known lower bound. It does not relax call/time limits or lost-accounting holds. Failed/invalid/timed-out attempts count too. Every provider turn needs completed usage: a measured turn followed by a failed, interrupted or truncated turn makes the whole attempt unknown. Abandoned attempts retain unknown usage and their open wall interval counts conservatively. A live adapter's birth identity postpones its unknown-usage decision until completion. Thresholds use >=. Call slots are reserved atomically before paid work; token/time limits can overshoot by already admitted concurrent calls. Existing stage timeouts still apply.

Progress is a separate opt-in policy. A turn is one completed background work stage (exit 0 or completed red build 14); wrappers and individual specialists do not add turns. Quiet waits (2, 10, 16, 23, 28, 29), handoffs, infrastructure faults, incomplete provider results, interruptions, withdrawals and holds do not advance it. An empty contract supplies no trusted progress and stalls after two ordinary completed turns. Fact IDs must be stable, 1–128 ASCII letters/digits/_.:-. Values contain exactly command_id (repo.test_command, qa.test or review.build) and the exact command. Configure that command as an actual runtime test gate too. The ticket CLI accepts execute-gate to run the configured command, never a caller's exit, HEAD or proof file. bureau_record_gate remains observational and cannot submit progress. A requirement or confirmed finding needs a command that proves that particular claim; a generic green suite cannot establish an unrelated claim. Facts are bound to the contract digest. Provider-reported completion/findings/applied fixes, checkboxes, commits and activity never qualify. A new fact resets the count once; replaying the same green gate at a new HEAD does not. Changing the contract requires fresh gate evidence.

The dispatcher's lane cap is the batch concurrency cap, agents.parallel_lanes, also used by orchestrate.sh --execute; there is no separate batch-budget knob. Numeric runtime settings

The shell consumers validate the numeric settings below after their source has been selected, including values inherited from the process environment. Accepted text contains only ASCII digits, at most ten characters, within the documented range. Leading zeros are decimal (010 becomes 10). An empty, signed, expression-like, oversized or out-of-range value uses the documented default and emits one warning line naming the key, never the rejected value. An absent setting (or a JSON null) silently uses its default. Zero is accepted only where the range includes it, such as disabling workbench panes or the in-flight cap.

The .env reader and precedence are unchanged: an accepted file entry replaces the inherited value; a rejected entry leaves it alone. The reader still rejects leading-zero text such as 010 for the keys on its numeric list, so use 10 in .env; inherited 010 and digit strings in JSON are normalized at consumption. Valid long budgets such as 5400 seconds per pass and 10800 seconds total retain their meaning. The existing Linear retry/request and merge-gate readers keep their documented source fallback and coercion rules.

queue-loop.sh validates its positional polling interval using the same 1–10080 minute range and 30 minute fallback. It exports BUREAU_QUEUE_POLL_SECONDS for the merge-gate picker; inherited values of that internal setting accept 1–604800 whole seconds and fall back to 1800 seconds when invalid. Without that override the picker uses agents.poll_interval_minutes.

The usage-signal fields pct (integer part, 0–100), reset_epoch and updated_epoch (whole seconds, 0–9999999999) are checked before shell arithmetic; invalid fields fall back to 0 with a warning naming the field. Fractional percentages keep their existing integer-part comparison. The already bounded shepherd merge wait/poll settings retain their base-10 and upper-cap behavior; their warnings now omit the rejected value.

Implementation results accept tasks_done from 0 through 100000 per pass; invalid counts contribute 0. The shared schema states this range in its field description because Claude rejects numeric minimum/maximum constraints; the shell enforces it for both providers. Alert-throttle log timestamps are checked before subtraction; a malformed record leaves its event unsuppressed. Counts and timestamps obtained from tools are also checked before shell arithmetic or numeric comparisons.

The shell environment filter reserves its own helper names (listed in _BUREAU_ENV_INTERNAL_NAMES in scripts/bureau-env.sh), including IFS and the _beb_*, _bec_*, _beh_* and wrapper locals in that list. Those exact names are removed from child environments and cannot be reintroduced through wrapper NAME=VALUE arguments. Other application variables keep the existing default/clean-mode rules.

Carrier checks read literal NUL-delimited names and values from /usr/bin/env -0, so an enclosing function's local variable cannot hide an exported secret carrier. Generic application names such as rc are not reserved. An isolated Python helper makes the per-entry decisions and returns only names to remove, or the allowed clean-mode entries. Bash validates the complete decision frame before decoding it; local secret values travel on stdin, never command-line arguments. Both transports use pipes, without a temporary file or here-string.

The snapshot interpreter is resolved once when bureau-env.sh is sourced, using only the system default PATH from /usr/bin/getconf PATH, with Bash's command hash cleared in the resolving subshell. It must resolve to an absolute path to an executable file. The helper uses that path with -I; a caller's PATH, hashed python3, shell function or virtualenv cannot replace it and receive the stdin secrets. Install Python 3.9+ on that system default PATH; having Python only on a custom shell PATH is insufficient. This restriction applies to the snapshot helper; other runtime tools retain their existing lookup rules.

The six-character embedded-secret threshold applies only when Bash's effective encoding and the helper's encoding are provably the same: their resolved nonempty CODESET names or locale identities must match. A matching character-probe length is insufficient; SJIS and GB2312 can count the same probe identically and a secret differently. Bash's highest-priority nonempty LC_ALL, LC_CTYPE or LANG binding supplies its locale identity; an empty declared binding may hide a still-active outer locale and makes that identity unknown. When the identities/codesets differ or cannot be established, every nonempty secret is removed anywhere inside another variable, regardless of length, for visible and hidden secrets alike. This can remove unrelated values containing a short secret, including allowed clean-mode variables. Exact copies are always removed.

With proven equivalence, the existing threshold is unchanged: visible secret copies use Bash's measured lengths, hidden exports use the actual exported locale and libc multibyte counting (UTF-8 uses surrogate-preserving decoding), and invalid bytes count individually. Thus a five-character UTF-8 secret such as äääää stays embedded in an otherwise allowed value, including clean-mode TZ, when the codesets match. The helper starts under C so older system Pythons can initialize even with an empty CODESET; the original exported locale comes from the snapshot. CODESET names are compared as identities, never used as Python codecs, so empty or unrecognized names cannot raise LookupError.

Measured snapshot-filter overhead on macOS is approximately 70–80 ms per wrapped call with system Python 3.9, versus 30 ms with Homebrew Python, across 20–1000 environment entries in default and clean modes. These are local measurements, not a performance guarantee; 100 calls can add roughly 7–8 seconds with system Python. The snapshot resolver currently follows the system default PATH described above; BUREAU_PYTHON does not override it. The Homebrew figure is a comparison measurement, not a change to the trusted interpreter selection.

No trusted interpreter, producer/helper failures, pipe failures and incomplete or malformed snapshot/decision frames stop before the wrapped child starts with 24 (environment-blocked). This holds for both environment modes and the curl scrub, including if and || callers, with or without set -e. Failure exits the calling shell; inside a subshell it ends only that subshell. The curl subshell scrub also refuses with 24 when a malformed host-variable name cannot safely be unset in Bash; the other wrappers remove it literally with env -u. The shell helpers support Bash 3.2 (including POSIX-mode sourcing) and require Python 3.9+ and /usr/bin/env with -0 (as on the supported macOS/Linux CI hosts). Snapshot ingestion does not require a writable temporary directory.

Risk tier

The acceptance brief includes a mechanical low, normal or high tier and the counts/paths supporting it. The tier changes no routing, holds, verdicts or merges; a human merges every PR. It does not enable automatic merging or change agents.merge_mode. Omitting agents.risk_tier uses these defaults:

{
  "agents": {
    "risk_tier": {
      "low_max_changed_lines": 100,
      "low_max_files": 5,
      "high_min_changed_lines": 1000,
      "docs_patterns": ["docs/*", "**/docs/*", "*.md", "*.rst"],
      "test_patterns": ["tests/*", "**/tests/*", "test/*", "**/test/*", "test_*.py", "*_test.py", "*.test.*", "*.spec.*"],
      "sensitive_patterns": []
    }
  }
}

Changed lines means insertions plus deletions in base..HEAD. Low requires at least one changed path, every path matching the docs/tests lists, at most 100 changed lines and 5 files, no binary files and no sensitive path. High wins whenever a sensitive path matches or changed lines reach 1000. Normal covers everything else, including missing diff metadata (which is stated explicitly). Threshold comparisons are inclusive. Renames count as delete/add; binary files count as files with no inferred line count.

Globs use case-sensitive shell-style matching against repository-relative paths; * can cross /. A slashless glob also matches any basename. Docs/tests lists replace their defaults. sensitive_patterns adds to these mandatory defaults; an empty list cannot remove them:

Evidence is automatic and needs no .bureau.json key or configuration-version change. <git common dir>/bureau/evidence/v1/ holds private (directories 0700, files 0600) metadata-only receipts, background manifests, gate digests and waits. It retains no log bytes, excerpts, command text, ticket descriptions or structured-result prose. Original provider files/transcripts remain pointers outside the store; receipt recovery needs the unchanged original and its matching digest. Linked worktrees share the locked store; separate clones/hosts do not.

Completed runs expire after 128 evictable runs or 30 days, deleting each manifest with its receipts. Resolved waits and inactive ticket observations expire after 30 days. A global 16 MiB/4,096 file budget includes atomic staging and abandoned temporary files and evicts oldest completed data first; active/interrupted runs, open waits and runs referenced by open waits are protected. Replacements reserve their full new size and one additional file slot, so even unchanged/shrinking optional updates can be refused. Optional write/housekeeping exceptions warn/skip; a success receipt that cannot fit prevents success forwarding. An already oversized store with protected or undeletable files requires operator inspection. Each tick/queue iteration attempts up to four open-wait tickets within a shared 10-second network budget, including manual-mode repositories with merge/rebase disabled. Persisted oldest-first cursors take priority when an unchanged cursor can be written and read back with enough staging room for the next timestamp. Only refused persistence selects in-memory rotation; fresh shell ticks seed it in configured poll-interval buckets. For a stable set of N readable tickets, an advancing clock and at least one read started per sweep, all are attempted within N sweeps with writable cursors; the refused-write fallback has the same bound in a retained dispatcher or independent ticks at the configured cadence (default 30 minutes). Other restart/cadence patterns have no cross-process fallback bound; see stage protocol. Exact end times require Linear completion history or PR mergedAt; other resolutions retain null event times.
