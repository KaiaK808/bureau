# Configuration reference

Every knob bureau-init exposes — what it controls, where it lives, and what the default is. Two surfaces:

- **`.bureau.json`** — written by `/bureau-init` to the target repo's root. Gitignored. UUIDs + agent toggles.
- **Environment variables** — runtime settings read by the pipeline scripts, set inline (`BUREAU_DRY_RUN=1 ./scripts/queue-loop.sh ...`), exported in the operator's shell or read from the installation's `.env`.

The pipeline scripts read the installation's `.env` selected by `BUREAU_ENV_FILE` (by default the `.env` next to `.bureau.json`). For a key accepted by the loader and defined in that file, `.env` wins over the process environment, including values exported in the operator's shell or set on the start line. For a key `.env` does not define, the environment value is used. Keys outside the loader's allow-list are ignored in `.env`.

For one run, use a per-stage key that `.env` does not define, or change or comment out the corresponding line in `.env` for that run and restore it afterwards. See the per-stage overrides below for the available keys and an example.

Setup captures the project-specific settings. Verify credentials, installed tools and real tests before running work. Current app tasks use the app-selected model; provider settings below select background CLIs.

## `.bureau.json`

### Version and validation

Version 1 remains compatible; version 2 makes the legacy `agents.runner: "claude"` default explicit. Migration preserves existing fields, adds `agents.model_compatibility: "v1"` to retain legacy provider model selection, and saves a private exact backup. `bureau-doctor.py` validates shape/version and reports effective settings without contacting providers. See [migration and rollback](migration.md).

### `agents`

Which pipelines run, how often they poll, how aggressive they are.

**Default semantics.** An absent stage is disabled. A boolean controls the stage directly; an object such as `{"enabled":true,"runner":"codex"}` is enabled unless `enabled` is explicitly false. The setup defaults below describe the initial configuration, not a fallback that enables missing stages. Preserve existing choices during updates.

Read [provider runtime](provider-runtime.md) for exact model precedence, sandbox capabilities and structured results. Code review/research default to read-only; spec-review/implementation/QA can write within the permitted workspace. The executor runs actual implementation/QA tests separately. Unknown runners, malformed results and denied permissions are errors, never automatic fallback to Claude.

Silence settings apply per creative provider call, alongside the existing hard timeout and implementation bounds; outside-gate commands retain their own wall-clock handling. Claude uses `--output-format stream-json --verbose --include-partial-messages` only with a nonzero silence window; unsupported CLI flags fail without falling back to an unobservable call. Native ownership inspection uses macOS libproc or Linux procfs and orphan adoption. A per-call inherited marker tracks detached descendants; a process that both clears that marker and detaches before observation cannot be identified. Review cancellation uses the same ownership cleanup even with silence disabled. Compare installation drift, resync all scripts including `bureau-activity.py`, and restart drivers before opting in. Qualification uses local fakes; test your installed provider CLI before production use.

Spec numbers are reserved per issue in `<git common dir>/bureau/spec-numbers.json` under a sibling `.guard` lock. The spec stage fetches and prunes all origin heads using the full wildcard refspec before reserving, invokes the pinned 1.2.2 feature helper with `--number`, and checks that the helper did not auto-correct it. Retries reuse the number and stable issue-key short name; gaps are fine. After a disposable worker reset, the stage checks branch ownership and checks out its reserved local/origin branch before creating artifacts or calling specify. Remote revisions fast-forward; unpublished local commits are retained; divergent history halts with 25 and needs-human. Lock acquisition is bounded to 300 seconds by default (`BUREAU_SPEC_LOCK_TIMEOUT` in the process environment, whole seconds 1–86400; invalid values warn with the key only and use 300). On timeout the stage prints the lock path, exits 124 and returns the issue to Triage before specify; this does not bound Git scanning after acquisition. The helper creates under `specs/`, so Bureau relocates its output for a different `repo.specs_dir` and persists the exact directory for later phases. Existing approved specs resume downstream; older issue-directory associations are not imported into reservations. Keep the registry across cleanup. Separate clones or hosts need their own coordination; the early cap check uses a Linear snapshot, while the common-directory spec-admission lock serializes the authoritative reservation and Spec move for every updated driver, including pending moves absent from lagging snapshots.

### Ticket run budgets and trusted progress

Ticket budgets are off by default. They cover every provider attempt for the issue in the same common Git directory, across stages, checker/verifier phases, worktrees, shepherd runs and dispatcher restarts:

```json
{
  "agents": {
    "ticket_budget": {
      "tokens": 200000,
      "provider_calls": 20,
      "wall_seconds": 14400,
      "allow_unknown_usage": false
    },
    "ticket_progress": {
      "enabled": true,
      "max_non_improving_turns": 2,
      "contract": {
        "fulfilled_requirements": {
          "required-behavior": {"command_id": "repo.test_command", "command": "bash tests/acceptance.sh"}
        },
        "qualified_gates": {
          "acceptance": {"command_id": "repo.test_command", "command": "bash tests/acceptance.sh"}
        },
        "confirmed_findings": {}
      }
    }
  }
}
```

Each dimension is independently optional; absent/null/0 disables it. Wrong types, unknown keys, negative/nonfinite limits or invalid contracts refuse execution with 24. Tokens/calls require integers; wall seconds may be fractional. Auth/help probes, deterministic shell checks and conflict-resolution validation receipts are not paid provider attempts; only identities admitted through the ticket ledger count. Wall time sums provider intervals, including concurrent calls, excluding idle queue time. Tokens include input/output plus Claude's disjoint cache-read/cache-creation input. Codex cached input is already included in input tokens. Every required counter must be reported; otherwise the attempt and aggregate token total stay unknown. Every valid reported counter still contributes to the known lower bound. Accounting is independent of `session.cost_tracking`.

`allow_unknown_usage: true` explicitly permits unreported tokens, retaining null totals and enforcing the known lower bound. It does not relax call/time limits or lost-accounting holds. Failed/invalid/timed-out attempts count too. Every provider turn needs completed usage: a measured turn followed by a failed, interrupted or truncated turn makes the whole attempt unknown. Abandoned attempts retain unknown usage and their open wall interval counts conservatively. A live adapter's birth identity postpones its unknown-usage decision until completion. Thresholds use `>=`. Call slots are reserved atomically before paid work; token/time limits can overshoot by already admitted concurrent calls. Existing stage timeouts still apply.

Progress is a separate opt-in policy. A turn is one completed background work stage (exit 0 or completed red build 14); wrappers and individual specialists do not add turns. Quiet waits (2, 10, 16, 23, 28, 29), handoffs, infrastructure faults, incomplete provider results, interruptions, withdrawals and holds do not advance it. An empty contract supplies no trusted progress and stalls after two ordinary completed turns. Fact IDs must be stable, 1–128 ASCII letters/digits/`_.:-`. Values contain exactly `command_id` (`repo.test_command`, `qa.test` or `review.build`) and the exact command. Configure that command as an actual runtime test gate too. Only runtime execution of that configured command, exiting 0 at unchanged HEAD with recorded output, qualifies. `bureau_run_gate` executes QA/review checks; the outside-gate executor runs verified recovery checks. The ticket CLI accepts `execute-gate` to run the configured command, never a caller's exit, HEAD or proof file. `bureau_record_gate` remains observational and cannot submit progress. A requirement or confirmed finding needs a command that proves that particular claim; a generic green suite cannot establish an unrelated claim. Facts are bound to the contract digest. Provider-reported completion/findings/applied fixes, checkboxes, commits and activity never qualify. A new fact resets the count once; replaying the same green gate at a new HEAD does not. Changing the contract requires fresh gate evidence.

The dispatcher's lane cap is the batch concurrency cap, `agents.parallel_lanes`, also used by `orchestrate.sh --execute`; there is no separate batch-budget knob. Lane limits bound simultaneous tickets; ticket budgets bound each ticket's spending. The legacy absent-setting defaults remain two dispatch lanes and three explicit batch lanes.

Inspect with `python3 -I scripts/bureau-ticket.py --repo . --issue TEAM-123 status`. Authoritative records live under `<common-git-dir>/bureau/tickets/TEAM-123.json`, outside prunable evidence. A sibling `TEAM-123.attempts.json` retains only ledger-admitted attempt identities. When either policy is enabled, initialization durably writes `<common-git-dir>/bureau/ticket-witnesses/TEAM-123.json` before creating the ledger. This marker is separate runtime state outside provider-writable worktrees, including for progress without provider calls. With a policy enabled and a witness present, a missing, empty or unreadable ledger, or missing admitted attempt rows, stops with 25 / `budget`, `accounting_lost: true`, even with unknown usage allowed. Keep the ledger, admission history and witness across cleanup. Receipts of any age or type never witness accounting loss or add paid attempts; old receipts without a ledger do not stop an upgraded repository with configuration `{}`. Invalid ledgers, including invalid nested stop reasons/exit pairs, fail closed with 24. With both policies disabled, accounting I/O failures warn without changing execution, including runtime finalization; accounting-loss policy holds are disabled too.

To resume, stop drivers, inspect preserved work and the ledger, reconcile ownership, and raise an exhausted limit if appropriate. A deliberate new lifetime allowance/progress reset requires `python3 -I scripts/bureau-ticket.py --repo . --issue TEAM-123 reset --acknowledge-accounting-loss`, outside a run environment and with no ticket ownership claim. Then clear the ticket's dispatcher skip/human hold. Deleting or emptying a witnessed ledger is not a reset command. Separate clones/hosts and calls bypassing Bureau's adapter are outside this local contract. Compare installed drift, resync all scripts together including `bureau-ticket.py`, and restart drivers before enabling. Tests use fake providers/services, real Git and per-guard negative controls; live adopter/provider qualification remains outstanding. See the [stop protocol](stage-protocol.md#ticket-budget-and-progress-stops).

### Advisory lesson budgets

`agents.lessons_budget_bytes` is an optional object with `spec`, `implement`, `qa` and `code_review` integer keys. Each defaults to **8192 UTF-8 bytes**, including the existing advisory wrapper, separators and truncation marker; each review specialist receives the same bounded context. Values 0–1048576 are accepted, `0` disables injection for that stage, and invalid values warn and fall back to 8192. For example: `"lessons_budget_bytes": {"implement": 12288, "qa": 4096, "code_review": 4096}` inside `agents`. On overflow, keep whole entries in deterministic order, skipping entries that do not fit and continuing to later entries, followed by the truncation marker; entries are never sliced. A single oversized entry is dropped, leaving the wrapper and marker if no entry fits. A budget too small for the complete wrapper and marker omits overflowing context with a warning. These are byte limits, not token estimates.

Curate `LESSONS.md` using the [entry format and selection rules](stage-protocol.md#bounded-advisory-lessons). Existing free-form files remain one untagged general lesson set, now subject to the same budget. Upgrade by resyncing the complete scripts scope, including `bureau-lessons.py` and its callers, and restarting drivers; `--update` alone does not install the helper. No lesson-file migration is required.

#### Deterministic conflict resolution

`repo.conflict_resolution.generated` defaults to `[]`. Each entry requires `globs` (nonempty array of repository-relative output patterns) and `command` (nonempty argument array, executed directly from the checkout root). Patterns are root-anchored: `*`, `?` and character classes match one path component; `**` spans zero or more components. `repo.conflict_resolution.append_only_paths` defaults to `[]` and contains exact repository-relative filenames, including root files such as `CHANGELOG.md`. Absolute paths, traversal and overlapping strategies are refused. No configuration migration is required; existing installations retain the legacy rules.

For Bureau's generated manual, cover **every** output of the renderer, which requires Pandoc:

```json
{
  "repo": {
    "test_command": "bash tests/run.sh",
    "conflict_resolution": {
      "generated": [
        {"globs": ["docs/site/*.html"], "command": ["python3", "scripts/render_docs.py"]}
      ],
      "append_only_paths": ["CHANGELOG.md"]
    }
  }
}
```

A configured repair requires an explicit `repo.test_command` containing a command; whitespace-only or comment-only strings decline, and there is no inferred fallback. Append-only means verified insertions anywhere, including under Unreleased. Rewrites, deletions, binary input, missing base/side blobs, mode changes, unterminated input and ambiguous repeated nonblank base anchors decline. Concurrent insertions sharing any nonblank inserted line also decline, including identical new headings or context: preserving side sequences alone cannot prove section associations. New ATX/Setext Markdown headings in either insertion also decline, since they could capture entries from the other side. After source conflicts resolve, `restore_worktree_deps` prepares npm dependencies against the merged manifests before any generator or check; preparation failure declines the repair. All configured generators then run in declaration order, each limited to its own full output set. Generator or check failure, unavailable commands (including Pandoc), undeclared edits or remaining conflict markers restore the saved clean checkout and use existing conflict exit 17. Rollback restores only paths changed since the snapshot and grants directory/parent access only when needed. Unchanged ignored content and modes stay untouched. A filesystem failure on one path does not stop other restores or the saved-index/Git reset attempt; incomplete restoration declines explicitly. Saved directory modes are restored after the reset. Commands run outside the provider sandbox under `repo.untrusted_env`, with a fixed 1,800-second limit per command. Checks must leave the tracked tree/index unchanged and create no nonignored untracked files; ignored test caches are permitted. See [the transaction contract](stage-protocol.md#deterministic-conflict-resolution) for rollback and ownership limits.

#### Python repositories

The stage worktrees are reset with `git clean -fdx`, which removes an ignored `.venv`. First commit the resynced scripts to `main`, so that the stage protocol the agents read in their worktree (`scripts/bureau-stage.md`) carries the rule for linked paths; then set `"repo": {"worktree_links": [".venv"]}` so every stage worktree gets a link to the main checkout's virtualenv, and make sure `.gitignore` lists `.venv` (not only `.venv/`); `bureau-doctor.py` shows whether it does. With an editable install (`pip install -e .`), the linked virtualenv's `.pth` file points at the **main checkout's** `src/`, not at the worktree's, so Python in a worktree imports the main checkout's code unless the worktree comes first on the path: run tests as `PYTHONPATH=src .venv/bin/python -m pytest` (or set it in `repo.test_command` or `scripts/bureau-test.sh`), and say so in the project instructions the agents read. The linked virtualenv is the main checkout's own: what an agent installs, recreates or deletes there happens to yours, and pull-request code that QA or the review build check runs uses it too. If that is not acceptable for a repository, leave the virtualenv out of `worktree_links` and let `repo.test_command` or `scripts/bureau-test.sh` create what the tests need.

### Numeric runtime settings

The shell consumers validate the numeric settings below after their source has been selected, including values inherited from the process environment. Accepted text contains only ASCII digits, at most ten characters, within the documented range. Leading zeros are decimal (`010` becomes 10). An empty, signed, expression-like, oversized or out-of-range value uses the documented default and emits one warning line naming the key, never the rejected value. An absent setting (or a JSON `null`) silently uses its default. Zero is accepted only where the range includes it, such as disabling workbench panes or the in-flight cap.

The `.env` reader and precedence are unchanged: an accepted file entry replaces the inherited value; a rejected entry leaves it alone. The reader still rejects leading-zero text such as `010` for the keys on its numeric list, so use `10` in `.env`; inherited `010` and digit strings in JSON are normalized at consumption. Valid long budgets such as 5400 seconds per pass and 10800 seconds total retain their meaning. The existing Linear retry/request and merge-gate readers keep their documented source fallback and coercion rules.

`queue-loop.sh` validates its positional polling interval using the same 1–10080 minute range and 30 minute fallback. It exports `BUREAU_QUEUE_POLL_SECONDS` for the merge-gate picker; inherited values of that internal setting accept 1–604800 whole seconds and fall back to 1800 seconds when invalid. Without that override the picker uses `agents.poll_interval_minutes`.

The usage-signal fields `pct` (integer part, 0–100), `reset_epoch` and `updated_epoch` (whole seconds, 0–9999999999) are checked before shell arithmetic; invalid fields fall back to 0 with a warning naming the field. Fractional percentages keep their existing integer-part comparison. The already bounded shepherd merge wait/poll settings retain their base-10 and upper-cap behavior; their warnings now omit the rejected value.

Implementation results accept `tasks_done` from 0 through 100000 per pass; invalid counts contribute 0. The shared schema states this range in its field description because [Claude rejects numeric `minimum`/`maximum` constraints](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#json-schema-limitations); the shell enforces it for both providers. Alert-throttle log timestamps are checked before subtraction; a malformed record leaves its event unsuppressed. Counts and timestamps obtained from tools are also checked before shell arithmetic or numeric comparisons.

The shell environment filter reserves its own helper names (listed in `_BUREAU_ENV_INTERNAL_NAMES` in `scripts/bureau-env.sh`), including `IFS` and the `_beb_*`, `_bec_*`, `_beh_*` and wrapper locals in that list. Those exact names are removed from child environments and cannot be reintroduced through wrapper `NAME=VALUE` arguments. Other application variables keep the existing default/clean-mode rules.

Carrier checks read literal NUL-delimited names and values from `/usr/bin/env -0`, so an enclosing function's local variable cannot hide an exported secret carrier. Generic application names such as `rc` are not reserved. An isolated Python helper makes the per-entry decisions and returns only names to remove, or the allowed clean-mode entries. Bash validates the complete decision frame before decoding it; local secret values travel on stdin, never command-line arguments. Both transports use pipes, without a temporary file or here-string.

The snapshot interpreter is resolved once when `bureau-env.sh` is sourced, using only the system default PATH from `/usr/bin/getconf PATH`, with Bash's command hash cleared in the resolving subshell. It must resolve to an absolute path to an executable file. The helper uses that path with `-I`; a caller's PATH, hashed `python3`, shell function or virtualenv cannot replace it and receive the stdin secrets. Install Python 3.9+ on that system default PATH; having Python only on a custom shell PATH is insufficient. This restriction applies to the snapshot helper; other runtime tools retain their existing lookup rules.

The six-character embedded-secret threshold applies only when Bash's effective encoding and the helper's encoding are provably the same: their resolved nonempty CODESET names or locale identities must match. A matching character-probe length is insufficient; SJIS and GB2312 can count the same probe identically and a secret differently. Bash's highest-priority nonempty `LC_ALL`, `LC_CTYPE` or `LANG` binding supplies its locale identity; an empty declared binding may hide a still-active outer locale and makes that identity unknown. When the identities/codesets differ or cannot be established, every nonempty secret is removed anywhere inside another variable, regardless of length, for visible and hidden secrets alike. This can remove unrelated values containing a short secret, including allowed clean-mode variables. Exact copies are always removed.

With proven equivalence, the existing threshold is unchanged: visible secret copies use Bash's measured lengths, hidden exports use the actual exported locale and libc multibyte counting (UTF-8 uses surrogate-preserving decoding), and invalid bytes count individually. Thus a five-character UTF-8 secret such as `äääää` stays embedded in an otherwise allowed value, including clean-mode `TZ`, when the codesets match. The helper starts under `C` so older system Pythons can initialize even with an empty CODESET; the original exported locale comes from the snapshot. CODESET names are compared as identities, never used as Python codecs, so empty or unrecognized names cannot raise `LookupError`.

Measured snapshot-filter overhead on macOS is approximately **70–80 ms per wrapped call with system Python 3.9**, versus **30 ms with Homebrew Python**, across 20–1000 environment entries in default and clean modes. These are local measurements, not a performance guarantee; 100 calls can add roughly 7–8 seconds with system Python. The snapshot resolver currently follows the system default PATH described above; `BUREAU_PYTHON` does not override it. The Homebrew figure is a comparison measurement, not a change to the trusted interpreter selection.

No trusted interpreter, producer/helper failures, pipe failures and incomplete or malformed snapshot/decision frames stop before the wrapped child starts with 24 (`environment-blocked`). This holds for both environment modes and the curl scrub, including `if` and `||` callers, with or without `set -e`. Failure exits the calling shell; inside a subshell it ends only that subshell. The curl subshell scrub also refuses with 24 when a malformed host-variable name cannot safely be unset in Bash; the other wrappers remove it literally with `env -u`. The shell helpers support Bash 3.2 (including POSIX-mode sourcing) and require Python 3.9+ and `/usr/bin/env` with `-0` (as on the supported macOS/Linux CI hosts). Snapshot ingestion does not require a writable temporary directory.

### Implement-pipeline retry loop

Env-only knobs (no `.bureau.json` equivalent). `implement-pipeline.sh` invokes the selected provider inside a bounded retry loop and parks the issue with `needs-human` if it doesn't reach `status: COMPLETE` within the budget.

| Var | Default | Notes |
|---|---|---|
| `BUREAU_IMPL_MAX_ITER` | `3` | Whole numbers 1–1000, fallback 3. Max provider passes per tick. Each iter parses the JSON status block, runs the squash-range check, pushes commits (see `agents.implement.push_each_iteration`), and decides continue/stop. Since v3.2 a pass that times out counts as one of them (status `TIMEOUT` in the iteration log) and the loop goes on; the stage ends with `124` only when the last allowed pass times out |
| `BUREAU_IMPL_ITER_TIMEOUT` | `1800` | Whole seconds 1–86400, fallback 1800. Per-iteration provider wall-time cap in seconds, limited by the remaining total budget and enforced by the Python adapter for both providers |
| `BUREAU_IMPL_TOTAL_TIMEOUT` | `5400` | Whole seconds 1–604800, fallback 5400. Budget in seconds for the implementation provider loop. Independent executor tests and publication can add time after it; this is not a monetary cap. Since v3.2 it, not one timed-out pass, bounds a stage whose passes time out; a timed-out pass that leaves 60 s or less of it ends the stage with `124`. Setting it to `BUREAU_IMPL_ITER_TIMEOUT` brings back the pre-v3.2 ceiling of one timed-out pass, but also caps a productive multi-pass run at that one pass's time; `BUREAU_IMPL_MAX_ITER=1` is the other trade-off (one pass of any kind) |
| `BUREAU_POST_IMPLEMENT_TIMEOUT` | `900` | Whole seconds 1–604800, fallback 900. Limit in seconds for `repo.post_implement_command`, never above `BUREAU_IMPL_TOTAL_TIMEOUT`. On timeout the hook's process group is ended and the stage halts with `14` |

The default provider-loop budget is 90 minutes, and since v3.2 a stage whose passes time out can use all of it: a timed-out pass no longer ends the stage while another pass fits (see [Exit 124](troubleshooting.md#exit-124-timeout--a-provider-pass-hit-its-time-limit)). An unproductive first `PARTIAL` iteration can become `STUCK`; a timed-out pass never does; prior productive iterations and legitimate `COMPLETE` results have separate handling. The executor checks Git evidence and, for Codex completion, the configured project tests. A provider's success text alone cannot complete the stage.

Terminal states map to PR state + Linear:

| Status | PR | needs-human label | State move | `logs/escalations.log` |
|---|---|---|---|---|
| `COMPLETE` | flipped to ready (`gh pr ready`) | no | → QA / Build Review | no |
| `NEEDS_HUMAN` / `STUCK` / `CAP_TIME` / `PARTIAL` | draft | yes | stays in Build | yes |
| `CI_MARKER` | draft, report posted on the PR | yes | stays in Build | yes |

`CI_MARKER` overrides every other status, `COMPLETE` included: a commit message in `origin/main..HEAD` carries an entry of `scripts/ci-skip-markers.txt` (`[skip ci]` and the other forms GitHub honours), or the range could not be read. Reword the named messages, then remove `needs-human`. The check also runs after every iteration of the loop, so a marker stops the run after the iteration that wrote it instead of after all of them, and that check's report goes into the iteration log of the summary; the `/goal` path, which has no iterations, checks once after its run, and the check before the hand-off always runs. The QA stage runs the same check and flags `needs-human` instead of routing on.

### Evidence storage and retention

Acceptance briefs and advisory insights add no configuration keys. Existing manual merge/stop settings trigger brief delivery; `evidence/v1/acceptance/NUMBER-HEAD.json` tracks pending/delivered ticket and PR destinations independently. Optional stage observations go to repository-shared `evidence/v1/insights.jsonl` (at most three single-line strings of 280 characters per provider attempt, 2,048 rows/30 days on collection). That advisory file is the explicit free-text exception to metadata-only evidence; it is never applied automatically. Both share the existing global evidence budget. Resync scripts and interfaces together, then restart drivers; see the [acceptance and insights protocol](stage-protocol.md#acceptance-briefs-at-human-merge-boundaries) for privacy, retention and delivery limits.

Failure insights and review dispositions also need no configuration key. The shell classifier `bureau-insights.sh` consumes runtime exits, provider metadata and trusted review/gate signals; model prose cannot choose a cause. All background stages can contribute filtered insights, including failed and held calls. Metadata-only `stage-outcomes.jsonl` and local `review-dispositions.jsonl` share the insight store's lock, private permissions, atomic capacity checks and per-ledger 2,048-row/30-day collection retention. A disposition has only its provenance, status, severity and filtered repository-relative path; applied/declined are advisory self-reports, not proof of a fix. Resync scripts and interfaces together and restart drivers; no backfill occurs. See [failure learning records](stage-protocol.md#failure-learning-records).

Evidence is automatic and needs no `.bureau.json` key or configuration-version change. `<git common dir>/bureau/evidence/v1/` holds private (directories 0700, files 0600) metadata-only receipts, background manifests, gate digests and waits. It retains no log bytes, excerpts, command text, ticket descriptions or structured-result prose. Original provider files/transcripts remain pointers outside the store; receipt recovery needs the unchanged original and its matching digest. Linked worktrees share the locked store; separate clones/hosts do not.

Completed runs expire after 128 evictable runs or 30 days, deleting each manifest with its receipts. Resolved waits and inactive ticket observations expire after 30 days. A global 16 MiB/4,096 file budget includes atomic staging and abandoned temporary files and evicts oldest completed data first; active/interrupted runs, open waits and runs referenced by open waits are protected. Replacements reserve their full new size and one additional file slot, so even unchanged/shrinking optional updates can be refused. Optional write/housekeeping exceptions warn/skip; a success receipt that cannot fit prevents success forwarding. An already oversized store with protected or undeletable files requires operator inspection. Each tick/queue iteration attempts up to four open-wait tickets within a shared 10-second network budget, including manual-mode repositories with merge/rebase disabled. Persisted oldest-first cursors take priority when an unchanged cursor can be written and read back with enough staging room for the next timestamp. Only refused persistence selects in-memory rotation; fresh shell ticks seed it in configured poll-interval buckets. For a stable set of N readable tickets, an advancing clock and at least one read started per sweep, all are attempted within N sweeps with writable cursors; the refused-write fallback has the same bound in a retained dispatcher or independent ticks at the configured cadence (default 30 minutes). Other restart/cadence patterns have no cross-process fallback bound; see [stage protocol](stage-protocol.md#versioned-background-evidence). Exact end times require Linear completion history or PR `mergedAt`; other resolutions retain null event times.

Resync all scripts together and restart drivers. A pre-fix PR 3 store can contain raw private copies: inspect active work and remove that old evidence store before using the metadata-only contract; resync does not scrub historical bytes. Do not delete evidence as a way to release ownership or authorize merging.

`python3 scripts/bureau-runtime.py waits [--issue TEAM-123]` prints the open causes and observed waiting share, counting overlapping waits once. Measurements cover the locally observed, retained period (at most 30 days); unknown exact resolution times stay null and first-observed ends yield an upper bound. `status --run RUN_ID` also reads background manifests. Resync scripts as a set, including `bureau-evidence.py`, then restart background drivers; no historical backfill. See [stage protocol](stage-protocol.md#versioned-background-evidence) for the record schemas and wait lifecycle.

## Resolution and provider usage

The actual creative invocation uses `bureau-provider.py`. Runner precedence is per-stage `BUREAU_RUNNER_STAGE`, stage JSON, default JSON, then Claude. Model precedence is provider-specific stage environment, generic stage environment, stage JSON, provider JSON, generic default JSON only for its owning default runner, provider environment default, and the legacy Claude environment default. See [provider runtime](provider-runtime.md).

`BUREAU_REASONING_STAGE`, `BUREAU_SANDBOX_STAGE`, `BUREAU_STAGE_TIMEOUT` and `BUREAU_CLAUDE_CONFIG_DIR` override the corresponding provider settings; like the other overrides on this line they are read from the process environment, not from `.env`. `BUREAU_CONFIG` selects the explicit configuration file; otherwise the current checkout and primary worktree are checked. `BUREAU_NO_MERGE=1` preserves the review boundary in background code review/merge entry points.

`BUREAU_CODEX_USAGE_FILE` supplies an operator-provided Codex signal (`pct`, `reset_epoch`, `updated_epoch`). A shared `BUREAU_USAGE_FILE` is usable by Codex only when tagged `"provider":"codex"`. Claude retains its legacy/ClaudeWatch sources. No signal means unknown usage and dispatch proceeds; provider quota failures are classified separately. Bureau does not scrape private Codex account files. The app's account-usage tool is independent of CLI token evidence.

Cost logs keep available CLI estimates separate from actual billed dollars (`null`). Missing Codex costs are never reported as zero. `bureau-status.sh --cost` displays `unavailable` when a total includes unknown values.
