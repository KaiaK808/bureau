## Context

Ownership of lifecycle, state and outward effects is spread over shell libraries, Python modules, signal/EXIT traps and many coordination files. Local fixes preserve individual boundaries but have not converged on one execution or recovery authority: a paid result, a comment and a state move can become durable separately. This record accepts the intended design on 2026-11-03; no implementation or cutover exists yet. Its citations identify current behavior to preserve or replace, rather than evidence that the new guarantees already hold.

## Options considered

- Continue patching shell/Python helpers, add a database wrapper or port constants only: smaller changes leave lifecycle, routing and crash recovery split across authorities.
- Use active-active hosts, lease expiry, labels or independent generation counters for takeover: simpler failover cannot fence a quiet live writer or its remote credentials.
- Dual-write JSON and SQLite, share SQLite over network storage or restore snapshots directly into live operation: migration convenience creates competing authorities or resurrects consumed work and effects.
- Claim exactly-once delivery, retry every timeout or rerun the stage to repair publication: acknowledgement gaps permit duplicate effects or repeated paid work; new IDs on retries lose operation identity.
- Record only a PID after spawn, nest bespoke supervisors or rely on shell traps: these leave registration gaps, reused-PID hazards and uncertain descendant survival after abrupt death.
- Use one environment allowlist, copy filters again or evaluate transported assignments: these lose role-specific credentials or literal-data safety and still provide no filesystem isolation.
- Load packages from the working directory, copy unversioned modules or introduce a new binary/registry/service framework: the former weakens trusted loading; the latter expands distribution before one complete path is qualified.
- Port every stage first or leave review publication/inline merge outside the pilot: the former expands qualification scope; the latter defeats the authority boundary being tested.

## Decision

**1. Execution authority.** One enrolled owning host runs one Python authority per repository; multiple owned attempts may coexist within it. App, CLI, scheduled and background starts all enter that authority. Bind repository/remote and tracker workspace/team/ticket identities, host/boot, run/attempt/launch identities, ownership generations and activation nonce; keep the migration epoch separate. Check generations before spawn, reset, result acceptance and effect dispatch. Silence, heartbeat loss and lease age never authorize takeover. Handoff pauses admission/publication, settles requests and children, proves containment empty, disables old activation/launchers and fences publishing credentials before verified export/import and a higher generation activate the target. For the first handoff, credential revocation plus verified source shutdown with restart quarantined is authorized; record proof of both before target activation. If either proof is unavailable, the source stays owner and the repository stays paused. Unresolved old sends remain uncertain; missing source history quarantines the repository. Sources: `templates/scripts/bureau-runtime.py:157`; `templates/scripts/bureau-runtime.py:167`; `templates/scripts/bureau-dispatch.py:452`.

Local facts establish execution/completion and stopped writers; strict tracker observations establish current eligibility. Pause, cancellation, withdrawal or a human hold removes start/publication authority without rewriting a completed result. Observed terminal states latch for that attempt; reopening requires explicit authorization and a new attempt. Unexpected active-state, input or PR-identity changes hold advancement for reconciliation. Remote Done remains distinct from local completion. Sources: `templates/scripts/bureau-config.sh:299`; `docs/exit-codes.md:67`.

**2. Contract as data.** One versioned, language-neutral JSON contract defines schemas, lifecycle/event enums, transitions/guards, typed effects, environment profiles and the complete exit table with stage/driver dispositions. Generate digest-bound Python validators/enums, Bash tables and public references; guard implementations remain reviewed code with conformance cases. Reference canonical provider schemas and the existing wire projection by hash. Keep attempt lifecycle, local completion, ticket authorization, containment and publication separate; BLOCK is a completed verdict plus a hold. Preserve nullable measurements, closed terminal reasons, every numeric exit/class and consumer exceptions, including 20/21/27/28/29; unknown/incompatible inputs authorize no transition. Sources: `templates/scripts/bureau-config.sh:4006`; `templates/scripts/bureau-config.sh:4027`; `templates/scripts/bureau-config.sh:4045`; `docs/exit-codes.md:67`.

**3. Store and cutover.** Use one private local SQLite store per repository on its owning host, outside ticket worktrees, with one writer service, short durable transactions, foreign keys and uniqueness constraints. Qualify local locking, WAL/full synchronization and backup capabilities; keep waits/network calls outside transactions. Commit completion and required effect intents together; retain original artifacts/Git objects by digest and reserve capacity before paid work. Inventory every writer/store, stop all legacy drivers and app writers, snapshot/import while inactive, reconcile uncertainty, then activate one higher epoch under an exclusive lock. No dual writing: retained JSON is only a stamped, rebuildable read-only projection. Unclassified files or surviving writers block cutover. Code rollback requires a compatible bundle using the latest database; old writers stay disabled. An older backup requires fencing, a new epoch and paused reconciliation of the lost interval before execution/publication, preserving terminal/effect tombstones; missing history stays quarantined. Sources: `templates/scripts/bureau-runtime.py:711`; `templates/scripts/bureau-runtime.py:1115`.

Freeze a verified per-ticket legacy round/cycle baseline from complete paginated history and local reservations/receipts. Unprovable pre-binding comments need operator attestation by exact comment identity/digest; ambiguity pauses admission and unavailable history never means zero. Preserve genuine header-only and marked counts, excluding copied foreign history. Before paid review, reserve a round bound to repository, tracker/ticket, run, attempt and generation. Subsequent observations count only with that reservation and matching publication identity/digest; copied footers, unbound markers and duplicate/retry/reuse observations add no round. Consumed reservations survive interruption; completed REQUEST_CHANGES reservations plus the imported baseline supply cycles to unchanged caps. Sources: `templates/scripts/bureau-config.sh:3806`; `templates/scripts/bureau-config.sh:3818`.

**4. Outbox.** Give each logical effect a stable operation ID bound to repository/ticket, attempt, type, destination and ordinal, retained across retries, migration and handoff. Freeze payload bytes/digest, prerequisites, per-ticket sequence and expected authorization/input identities; changed bytes or heads need a new authorized operation. The four states are pending (durable intent with no unaccounted send), acknowledged (validated response or remote proof; never resend), outcome-unknown (may have applied; reconcile and block dependents), and failed (definitive rejection or invalidated authorization; terminal). Persist a transport attempt before dispatch; a missing committed acknowledgement means outcome-unknown, even after a pre-write crash. Return it to pending only with non-application proof or qualified same-ID idempotency. Reconcile comments through complete paginated reads, destination/author identity, operation marker and exact body digest; absence alone never permits reposting. Publication recovery never reruns paid work. Sources: `templates/scripts/bureau-config.sh:1418`; `templates/scripts/bureau-config.sh:1713`.

Serialize requests per ticket and acknowledge required predecessors before advancement; recheck activation, holds, tracker/input/PR/head/base identity, configuration and prerequisites before every send/retry. BLOCK atomically records its hold and may publish specifically authorized hold/report effects unless an external hold or withdrawal supersedes them. Tracker moves retain an observational guarantee: strict pre-read and history reconciliation refuse observed changes, but the unconditional mutation can overwrite a human move made after the read. Acknowledgement proves application, not preserved intent; observed conflict holds further work, with no blind replay or compensating move. Adopt boolean agents.review.pr_comments, default true; invalid values refuse with 24. False suppresses all review-related PR comments, helper/status lines and PR briefs/evidence packets while preserving tracker reports, local results and evidence. Invalidate unsent PR intents as failed/publication-disabled; uncertain sends stay uncertain with retries disabled, and re-enabling resurrects nothing. Brief delivery remains observational and PR suppression never blocks required tracker routing. Sources: `templates/scripts/bureau-config.sh:1321`; `docs/adr/0012-human-boundary-briefs-and-local-insights.md:20`.

Treat outbox bodies as separately governed private prose, outside metadata evidence: project/filter/limit before freezing, never log bodies, use owner-only database/WAL/backups on an encrypted host volume and keep publisher credentials with the authority. Retention maximums are seven days after acknowledgement for bodies, thirty days for unresolved bodies and encrypted backups, and repository lifetime for compact operation/terminal-attempt tombstones. Repositories may shorten body retention; body storage stays off until applicable policy approval. Expiry/deletion blocks future sends and preserves uncertainty/tombstones; purge local copies and expire backups. Recovery reapplies deletion history before publication; missing history discards restored prose and quarantines effects. SQL deletion alone is no media-erasure proof. Sources: `templates/scripts/bureau-config.sh:4601`; `docs/adr/0012-human-boundary-briefs-and-local-insights.md:20`.

Commit intent/claims, create discoverable containment and launch a gated bootstrap; durably register host/boot, nonce, start identity and scope before a one-use GO permits useful work. Require durable hashed result artifacts and exact-attempt recovery; failed/cancelled/timed-out work cannot become success. Adopt only verified survivors with a working control channel, otherwise stop and prove empty or retain a hold/workspace. Linux unattended operation requires a discoverable per-attempt scope surviving supervisor death; macOS process-group compatibility retains uncertainty holds. Never release/reset/start successors while containment is unresolved; preserve 25/124/130 and withdrawal precedence. EXIT traps report cleanup, while the authority owns publication. **6. Environment profiles.** One Python builder consumes literal exported bytes, an explicit contract-defined role and validated overrides; shell uses a NUL-framed bridge without copied policy. Profiles preserve provider-only login/network additions, local-tool filtering, destination-authorized remote tools, compatible default untrusted environments and minimal clean environments. Service secrets/carriers, startup hooks and reserved settings remain filtered; stages cannot select publisher authority or override identity/containment. Preserve the six-character carrier threshold only with proven encoding identity; malformed transport, unknown profiles or unsupported encoding fail before spawn with 24. **7. Distribution and trusted loading.** Continue stdlib-Python source-bundle installation; extend recursive packages while preserving preview/customization conflicts. Hash/version the contract, generated bindings, modules and adapters as one immutable manifest, activated outside ticket worktrees. Pin the trusted launcher/interpreter/bundle, resolve installation symlinks and load only the verified package root under isolated Python; reject working-directory/PYTHONPATH/user-site substitutions, symlink escapes, unexpected files and mixed bundles. Compatibility entrypoints carry no publishing credentials. Negotiate protocol, contract digest/major, capabilities, bundle, schema read/write range and epoch before claims/spawn/effects; incompatibility refuses with 24. First slice.** Enable supervised code review through acknowledged tracker routing on one explicitly selected manual-merge repository, one review lane and a configured Merge state; retain the released merge-mode default elsewhere. Include shared prerequisites and every reachable early-error, reuse, round-start, PR/tracker report, state/label, brief and alert write. ## Rationale

One authority can transact local completion with its recovery obligations without pretending SQLite and remote services share a transaction. Stable effect identities separate paid execution from delivery; fencing and explicit uncertainty preserve ownership when evidence is incomplete. A complete review-to-routing slice proves these boundaries together while retaining existing deterministic policy. Generated contracts and role-specific environments remove duplicate meanings without delegating guard decisions to data or models.

## Consequences

Partial supersession takes effect only as each path migrates: ADR 0001, Isolated stages with a shared provider and exit protocol, moves lifecycle handling out of the adapter; ADR 0003, Metadata-only evidence with mandatory success receipts, changes coordination storage; ADR 0009, Literal environment filtering and validated shell arithmetic, replaces shell filter/snapshot ownership; ADR 0010, Five fixed conflict rules and explicit escalation, changes the pilot's semantic-conflict recovery route; ADR 0011, Independent review with optional Codex review of Claude builds, moves shell verdict/publication authority; ADR 0012, Metadata briefs at human boundaries and local advisory insights, replaces its separate delivery ledger. Their statuses stay unchanged. Stage boundaries, exact-attempt receipts, privacy limits, verdict floors and observational briefs remain.

Preserve ADR 0002's explicit merge authority and just-in-time CI/base/head gates; ADR 0004's committed spec checkpoints/governance; ADR 0005's machine-proven outside gates and single publication hop; ADR 0006's canonical schemas/wire projection; ADR 0007's admission/number reservations; ADR 0008's narrow preserved-worker reuse; ADR 0010's bounded mechanical rules; and ADR 0013's optional gate delegation. Enforcement migration changes no eligibility rule, and this record promotes no proposed ADR.

Implementation requires an installation-drift comparison, complete writer inventory, conservative import and coherent resync/activation. There is no upgrade action now. Future cutover disables incompatible entrypoints and other unmigrated stages on the pilot; private payload storage, containment qualification and operator reconciliation add costs. Prose retention grants no permission to copy transcripts into metadata evidence.

## Known limits

No implementation, new-design tests, live-service qualification or measured improvement exists yet. Single-host ownership provides neither automatic failover nor cross-service exactly-once delivery. Remote credential fencing cannot retract an accepted request or prove local writers stopped. The tracker read/write race can overwrite a human terminal move and incomplete history may never reveal it; acceptance must demonstrate that race with the actual unconditional mutation and subsequent hold, without compensation.

macOS process groups cannot prove exclusion of every detached descendant; unresolved containment blocks unattended release. Environment filtering cannot conceal same-account readable files, the database supplies no encryption itself, and privileged raw snapshot replacement is unsupported. Missing originals, payloads, deletion history or remote proof preserve holds rather than authorizing reconstruction, resend or paid rerun. Installation/fixture success does not qualify a live owning host. Automated merge, semantic repair, other-stage migration, model fallback and distributed operation remain outside the pilot.

## Reversal condition

Replace this design if qualified operating evidence shows that one authority cannot preserve the existing policy and crash/identity boundaries, or requirements demand multi-host execution/availability. Revisit only with an alternative coordination, credential-fencing, privacy and recovery contract demonstrated under faults.
