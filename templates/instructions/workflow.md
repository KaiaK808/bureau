## Bureau workflow

Configuration: `.bureau.json`. Read its team, state, label, and repository settings before acting on a ticket. Pipeline templates and scripts are the source of truth for stage behavior.

Spec Kit skills are in `{{SKILLS_DIR}}/speckit-*/SKILL.md`. Use `{{INVOKE}}speckit-specify`, `{{INVOKE}}speckit-plan`, and `{{INVOKE}}speckit-tasks` for the specification flow. Preserve `.specify/memory/constitution.md` and project decisions. Bureau commands include `{{INVOKE}}linear-to-spec`, `{{INVOKE}}linear-implement`, and `{{INVOKE}}bureau-learnings`.

During specify and plan: no measurements, probes, benchmarks or full test-gate runs. Use existing evidence and record unknowns for implementation/QA. In spec.md, place `## Governance and security` with `Decision:` and `Rationale:` lines at column 0, in plain text, before any code block or HTML block; a leading YAML front matter block is allowed. Use `Decision: required` or `Decision: not required` and explain applicability. A justified not required decision is valid; empty headings, placeholders, TBD and unexplained N/A fail the shared validator in spec review and app completion. These are Bureau requirements; preserve adopting repositories' customized `.specify/templates` and constitution.

Resolve Spec Kit dotted hook names such as `speckit.git.feature` to the installed native `speckit-git-feature/SKILL.md` under the host's skills directory. Read arguments from the current request; a literal `$ARGUMENTS` placeholder does not mean the request is empty. Follow enabled mandatory hooks while preserving an already prepared run and its canonical branch.

On every branch, including numeric feature branches, `codex/*` and detached checkouts, resolve the issue's exact approved feature directory before calling Spec Kit helpers. `create-new-feature.sh` mints a new number and directory on every call, so run it only when the ticket has no approved spec directory yet; on retries and later stages resolve the existing directory instead. Always pass both `SPECIFY_FEATURE=NNN-approved-feature` and `SPECIFY_FEATURE_DIRECTORY=specs/NNN-approved-feature` to every helper invocation that consumes an existing feature, using actual configured paths. Fresh worktrees lack the ignored feature.json, and 1.2.2 no longer derives the directory from the Git branch. SPECIFY_FEATURE alone cannot supply the directory or override a stale pointer. Do not guess from duplicate prefixes, change the issue branch or overwrite another feature's plan.

Resolve issue branches from the `<!-- bureau-branch: ... -->` comment marker. Work on the issue's feature branch, reference the issue in commits, and preserve existing user changes. Background queue scripts operate on disposable worker worktrees; do not run their reset/clean operations on the current app task's checkout.

Follow the requested stage boundary. A request for a spec or review does not authorize implementation or merging. Who merges after an approving background review is set by `agents.merge_mode` in `.bureau.json`: with `auto` and the merge agent on (`agents.merge` and a Merge state), the review moves the ticket to Merge and the merge stage merges through its gate; with `auto` and the merge agent off, the review itself merges inline through the same gate; with `manual`, the review parks the ticket in Merge and a human merges. Never take a merge route for a review-only request; the drivers' `--no-merge` (`BUREAU_NO_MERGE=1`) stops a background review before either automatic route.

`logs/events.jsonl` contains pipeline events. `{{INVOKE}}bureau-learnings` drafts `LESSONS.proposed.md` for review; existing curated lessons remain advisory and must be preserved.

In Codex, use `$bureau` for current-task stages, status and resume. It uses the shared local ownership protocol and preserves the app checkout.
