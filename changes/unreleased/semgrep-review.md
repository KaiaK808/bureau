section: Security

- Add opt-in offline Semgrep CE evidence to code review and a receipt-bound blocking merge recheck. Independent specialists judge first; the bounded scanner projection joins the all-role late step. Rules, suppressions and extra rules come from the PR base, the installed site-packages are verified against a shipped manifest before every run, the scan runs under network denial, and reports are written once to durable attempts. Advisory mode reports and continues; blocking mode holds on new findings at the configured severity and on unavailable or incomplete measurements, and keeps BLOCK and the review caps. **Upgrade:** compare installed drift, resync the complete scripts scope and restart drivers; existing repositories stay disabled. Before enabling it, install Semgrep 1.183.0 into a standard-library venv from the shipped wheel-only hash lock; this release ships manifests for macOS arm64 with CPython 3.14 and Linux x86_64 with CPython 3.12, and an eligible scan with any other interpreter reports unavailable. Empty eligible sets pass as not applicable without scanner prerequisites. Scanner PATH is exactly `/usr/bin:/bin`, and finding lines use LF byte boundaries. Blocking scans precede the existing final merge gates; a changed head, base ref or base commit then waits for the next tick. Validation: offline fake-venv tests for the scanner boundary, manifest generation, review, reuse and merge; one maintainer run of the pinned 1.183.0 on macOS arm64 under the network sandbox, covering every rule fixture, a hostile `.semgrepignore` and inline `nosemgrep`. Linux isolation on deployment hosts and adopting-repository qualification remain separate checks.
