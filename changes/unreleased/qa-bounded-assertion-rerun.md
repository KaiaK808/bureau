section: Fixed

- QA's final test gate allows one bounded rerun only for complete, named unittest/pytest assertion failures; pytest summaries must identify an assertion, and crashes, timeouts, zero tests, cleanup failures and environment denials (including read-only filesystems) are not retried there. Only failure diagnostics are classified, so test names such as `test_timeout` never block a rerun; unittest and pytest traceback file and function names are ignored as well, while exception messages still count. Known limit: pytest long tracebacks that print a test class instance named after a timeout, sandbox or teardown can still suppress the rerun; that case fails safe (no rerun, QA stays red). Phase 1 keeps its existing whole-gate retry on any nonzero exit and separate evidence/logs. Simple native commands select failed cases; other commands rerun the gate, requiring complete verbose case identities from both runs and passing coverage of every original case; counts alone stay red. A recovered final gate records a bounded `flaky` marker, keeps both logs and reports the flake in the QA comment and acceptance packet. Implementation gets no-change guidance only for a QA bounce carrying a recorded flake; ordinary QA and human feedback keep their prompt bytes. **Upgrade:** compare installed drift, resync the complete scripts scope and restart drivers; final QA gates now default to 900 seconds per attempt (`BUREAU_QA_TEST_TIMEOUT`, 1–86400). Older evidence readers must be upgraded together to read flake metadata; unfamiliar test output keeps the ordinary failure path. Validation uses focused local fixtures, fake services, assertion/environment and substituted-case controls, baseline prompt comparisons and a retry-disabled mutation independent of Git history; live providers, adopting-installation drift and the full suite remain maintainer checks.
