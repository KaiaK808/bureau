section: Changed

- Repository changelog entries now use one validated fragment per change under `changes/unreleased/`, avoiding shared Unreleased edits across pull requests. Contributors run `python3 scripts/changelog.py check` or `render`; maintainers run `release VERSION DATE` to collect and remove fragments. Release stages originals by rename before atomically replacing the changelog; interruptions restore unreleased fragments or preserve a committed dated section, and failed recovery or cleanup reports retained staging files. Reconcile any `changes/.release-*` directory before `check` will pass or another release can run; its diagnostic says whether staged files are released or must be restored. **Upgrade:** none for adopters; this concerns contributors to this repository only. Validation uses focused fragment, merge-order, release/refusal, pre/post-replacement interruption, failed move/restore/cleanup, atomic-write and malformed-input fixtures with recovery controls, the documentation check and the public-reference guard; the full suite and hosted CI remain maintainer checks.
