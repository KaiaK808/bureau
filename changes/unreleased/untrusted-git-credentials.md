section: Security

- Branch-controlled commands and agents now disable stored Git credential helpers and terminal prompting by default in both environment modes, preserving inherited counted configuration and dropping inherited `GIT_CONFIG_PARAMETERS` entirely so an included file cannot restore helpers after the reset. Malformed inherited counts discard all inherited counted pairs and start the reset at entry 0; invalid settings refuse with exit 24; Bureau's own git and gh environments retain their credential behavior. The setting is honoured on every path that builds that environment (agents, ticket gates, conflict commands, changed-test measurements), and the environment is validated before a gate's process hold is created. The reset switches off `credential.helper` lookup only: `GIT_ASKPASS`, `SSH_ASKPASS` and a configured `core.askPass` are not changed and can still supply a password, so an operator who uses askpass for private remotes keeps that exposure. **Upgrade:** resync the scripts together; installations whose test gate or post-implement command fetches from a private remote with a stored credential must set `repo.untrusted_git_credentials` to `"keep"` or supply another authentication method. Validation: focused regressions compare Python and shell output for empty, nonnumeric, negative and oversized counts, with and without inherited pairs, in both environment modes; real gate commands receive the reset and leave no process hold; local precondition probes verify exit 24 for invalid settings.
